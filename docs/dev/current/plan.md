## 0. 周期目标

本周期不追求新增展示功能，而是把已经存在的状态、评判、战术和多联赛接口收敛为可验证的公共契约：

1. 外部调用者不能直接修改比赛真相；
2. 球态、阶段和事件账本不再由旁路字段重复表达；
3. 战术/防守档案通过机会与责任链改变行为，而不是只改变标签或目标点；
4. 每个保留的能力维度都有端到端消费和负面对照；
5. NBA/FIBA 的规则差异由 profile 情景矩阵证明，而不是由类型存在推断。

## 1. 执行纪律

- 一个任务只有在代码、针对性测试和守卫都通过后才能关闭；
- 运行结果必须标明 seed、scope、league profile 和输出模式；
- 行为参数改动先用规则覆盖做 A/B，再决定是否改默认值；
- 结构重构与行为校准分开提交和验收；
- 黄金哈希只证明确定性/变化可追踪，不能替代因果、能力或真实度证据；
- 当前状态只更新 `docs/dev/status.md`，原始输出进入 `docs/dev/evidence/`。

## 3. D7 · 收敛 `MatchEngine` 公共边界

### 3.1 工作项

- 把 `physics`、`rng`、`rules`、`decision`、团队/战术配置等公开字段改为内部字段或不可变句柄；
- 设计最小只读 `snapshot`，让 CLI、回放、评判和测试不再依赖内部布局；
- 将强制场景与测试后门集中为命名明确的 `*_for_test` API；
- 扩展 `check_world_privacy.py`，检查 API 形态和禁止的公共真相字段，而不只是固定字段名；
- 保持事件流和黄金哈希的变更可解释，若输出契约改变则同步 protocol/schema 测试。

### 3.2 出口门

- 正常外部 crate 无法写入比赛真相字段；
- privacy guard 正常与负面对照都通过；
- engine、CLI、debug-server、WASM 和测试改用 snapshot/访问器；
- 至少一场固定输入回放与改造前具有等价的事件语义，或记录有意行为变化。

## 4. D8 · 球态和阶段边界

### 4.1 工作项

- 明确 `BallControl`（归属/最后触球）与 `BallMotion`（持球、飞行、松球、死球）的责任边界；
- 删除 `carrier_idx`、`ball_pos_3d` 等旁路字段作为权威来源的路径，保留时只能是派生缓存；
- 将 engine 的兼容别名收敛到 domain 的球态接口；
- 把 `step_inner` 分解为带窄签名的阶段函数，阶段写权限与顺序可审计；
- 为每条状态边、死球程序、罚球程序、节末和发球程序补充正向/负向测试。

### 4.2 出口门

- 非法球态边在 domain 测试中被拒绝；
- 每个球权变化都能回接到一个事实事件；
- `InvariantPhase` 是所有正常和短路路径的必经校验；
- 不存在由两个可写字段共同决定 holder/possession 的路径。

## 5. D9 · 战术和防守责任链

### 5.1 工作项

- 统一从版本化战术档案生成机会；旧 `TacticalSet` 只能作为解析/兼容层，不能继续承担主路径几何分支；
- slot fill、对位、协防、换防、恢复和轮换都输出结构化责任，而不是只输出目标坐标；
- 让 `DefensiveSystem` 的档案字段进入决策候选、执行重校验和结果解释；
- 删除无消费字段和 roster-order fallback；
- 为每个档案字段建立“输入 → 行为 → 结果”的控制场景和比赛场景测试。

### 5.2 出口门

- 新增进攻/防守档案不修改引擎 Rust 分支；
- 至少两种进攻档案和三种防守方案在固定输入下产生可解释的过程差异；
- 防守方案的方向性断言（例如沉退更收缩、紧逼更靠前）通过；
- 方案改变结果时，变化能通过事件/决策 trace 解释，而不是只有哈希变化。

## 6. D10 · 能力和倾向响应覆盖

### 6.1 工作项

- 生成维度 → 消费点 → 观测量 → 测试的清单；
- 为罚球、外线/内线防守、前/后场篮板、无球感觉和决策质量补齐端到端链路；
- 每条链同时提供正向扰动和故意断路负面对照；
- 检查规则曲线是否只是把能力值乘到一个结果上，而没有改变机会、执行或裁决；
- 删除无法证明消费链的维度，或把它们标为未批准提案而不进入运行 schema。

### 6.2 出口门

- 每个保留维度至少有一个可观察的单调响应；
- 反事实场景能区分“能力变化”和“档案/规则变化”；
- 断路后测试必红，恢复后必绿；
- 扰动证据不依赖 roster 顺序、球员 ID 或固定剧本。

## 7. D11 · NBA/FIBA 情景矩阵

### 7.1 工作项

- 为时钟、进攻时钟、犯规上限、bonus、罚球、三分几何、交替拥有和节末程序建立 profile 级情景 fixture；

### 7.2 出口门

- NBA/FIBA 情景测试分别通过；

- 任何仍未覆盖的程序被列入 status 的开放问题，而不是写成“多联赛完成”。
