# NBA-Sim · 比赛过程与真实性验证设计

> 本文档是五层验证的实施规格。比赛规则与统计记账语义归属 `docs/basketball.md`，战术输入归属 `docs/tactics.md`，质量通用要求归属 `docs/quality.md`。下文标记“新增”的类型和字段均为实施要求，不表示当前代码已经提供。实现状态记录在 `docs/dev/status.md`，实施队列记录在 `docs/dev/current/plan.md`。

## 1. 验证目标与结论

### 1.1 五层职责

1. **流程完整性**：已出现的触发条件是否得到完整处理；场景集是否覆盖所有必需路径。
2. **事实正确性**：规则、因果、运动和记账能否从原始事实独立重建。
3. **分布真实性**：在相同适用人群和统计定义下，模拟分布是否与真实比赛等效。
4. **机制有效性**：输入如何影响机会、选择、执行及结果；直接效应和全场反馈分别验证。
5. **组合真实性**：空间协作、攻防交互、条件分布和跨回合依赖是否符合独立证据。

跑位与战术贯穿五层。单个合法的防守失位、传球失误、战术被破坏或投篮不中均可成为正常比赛样本。记录自相矛盾、规则处理错误或物理不可能属于结构缺陷。合理比赛失误的频率和条件关系由第 3、5 层判断。

### 1.2 裁决与执行状态

`Verdict` 保留四态：

- `Pass`：证据充分且符合本条判据。
- `Defect`：充分证据证明不符合本条判据。
- `NotApplicable`：适用条件明确为假，且检查范围完整。例如一次普通传球无投篮判罚义务。
- `InsufficientEvidence`：字段、真实参考、样本量或检验精度不足，或统计区间无法决定等效性。

执行状态独立使用 `Completed`、`InputError`、`ExecutionError`。坏行、缺少协议必填字段、文件损坏、写入失败、运行超时立即终止该任务，返回非零退出码；已写出的诊断保留，禁止把执行错误转换为 `NotApplicable`。旧版本合法流缺少新能力时，可给能力项 `InsufficientEvidence`，不能参加要求该能力的完整认证。

完整运行中，触发机会数 = `Pass` 数 + `Defect` 数 + `InsufficientEvidence` 数。`NotApplicable` 单列，不进入触发机会分母。所有适用准则必须有记录，包括零机会记录；必需定向场景没有触发目标时，该场景测试失败。

### 1.3 严重度与完成条件

每条准则登记 `gate_class`：`Integrity`、`Mechanism`、`Distribution`、`Diagnostic`。前三类分别阻断对应认证，`Diagnostic` 只说明观察事实。严重度由具体子准则固定，禁止根据一次结果临时改变。

三个完成状态分别报告：

- `ValidatorImplemented`：登记的检查、解析、重建、场景、工件和 CLI 均实现并测试通过；验证器能正确表达数据缺口。
- `EngineConformant`：必需结构场景、全场结构检查和机制实验通过。
- `RealismValidated`：指定联赛、规则版本、阵容范围下，第 3、5 层全部必需参考与判据通过。

任何必需项的 `InsufficientEvidence` 都阻止对应完成状态成立。综合指数不得抵消失败或未判定。报告必须显示认证适用范围，禁止宣称对任意阵容和所有联赛都真实。

## 2. 独立篮球语义与统计记账

### 2.1 联赛依据

新增版本化 `BasketballRuleProfile` 与 `ScoringProfile`。前者描述联赛比赛规则，后者描述官方技术统计及回合口径。每条规则记录 `rule_id`、联赛、规则版本、出处条款、解释案例及审核状态。只有 `approved` 的规则可参与正式验收；缺少依据时阻止规则认证，不能依据模拟输出设定规则。

验证器可以共享单位转换和基础几何库，必须独立实现规则重建与统计记账。不得调用生产投篮结算、犯规结算或生产箱体累计函数来计算预期值。每条正式规则必须具备独立来源案例与边界案例；参考数据的官方箱体用于交叉核验。

`GameRules` 可以包含数值积分和行为参数；正式 NBA/FIBA 认证前检查其中的比赛规则字段是否符合指定 `BasketballRuleProfile`。自定义规则模拟只取得自定义范围内的结构结论。

### 2.2 投篮、封盖与判罚

将一次投篮动作、篮球离手、飞行接触、规则裁决和统计投篮记录分别保存。

- 离手前准备动作被拨球中断、已经构成投篮尝试时被封盖、离手后合法封盖，分别记录动作阶段和统计判定依据。不能只依据有无 `SHOT_RELEASE` 决定 `FGA`。
- 离手后的合法触球更新实际球运动。触球可以阻断原轨迹，也可以改变轨迹后继续飞行；最终结果依然可能为命中、投失、出界或规则裁决。原轨迹不得继续独立产生第二个结果。
- 未触筐投失、触板投失、触筐投失分别记录；篮板控制依据球的真实位置与控制事实。进攻时钟是否重置由触筐、控制和规则共同决定。
- 干扰球与篮筐干涉独立裁决；合法封盖的判据包含球的飞行阶段、篮筐附近位置及联赛条件。
- 有效命中计 `FGM` 和 `FGA`；普通有效投失及符合记账定义的封盖投失计 `FGA`；投篮犯规未中、进攻犯规使投篮无效等情形按 `ScoringProfile` 处理。二分、三分投失罚球及有效命中加罚分别裁决。
- 技术罚球等附加得分保留独立判罚身份，不能自动终结正在进行的进攻回合；罚球后的球权读取罚则。

新增 `ShotAttemptResolved` 记录 `shot_id`、物理结果、有效性裁决及规则依据；独立统计器据此及原始接触、时钟事实计算 `FGA/FGM/BLK`，并核对引擎声明的统计。

### 2.3 球权、回合和失误

引擎的 `PossessionSummary` 是待核对输出。验证器从控制建立、有效进球、罚球组、球权授予和节末事实重建 `PossessionRecord`，再比较引擎总结。

- 进攻篮板继续本队进攻；防守篮板或抢断导致控制转换。
- 投失后对方取得篮板记投篮及篮板，不能自动归为失误。
- 前场篮板、点球与短暂松球不单独增加回合数；以控制建立或规则授予作为边界证据。
- 普通进球及其加罚作为同一次进攻处理，最终罚球后的球权依规则决定；附加技术罚球使用独立得分归属，不制造新的普通回合。
- 失误责任使用 `Player(player_id)` 或 `Team(team_id)`；球队责任不能随意指定给在场球员。个人失误加球队失误等于球队总失误。
- 节末已建立控制但未形成出手的回合按冻结的统计口径计数；只有发球授予且比赛未重新开始的时段单列。真实与模拟数据使用同一回合定义，无法重建的真实样本不得填补。

球队技术统计原因使用规范分类 `BadPass`、`LostBall`、`OffensiveFoul`、`Violation`、`TeamViolation` 及规则明确的其他类型。现有 `TurnoverPassTipped` 等过程分类另存为过程标签，通过版本化映射联系统计分类，禁止假定二者相等。

### 2.4 时间与终局

协议同时保留整数 `tick_index`、单调 `simulation_time`、节内倒计时 `game_clock`、`shot_clock`、二者运行标志、节次和进攻方向。物理时长、比赛钟运行时长、活球时长分别累计；不得用模拟总耗时计算官方 Pace。

比赛钟归零时禁止启动新的无资格动作；已在截止前合法离手的投篮继续结算，需完成的判罚也继续执行。所有可能影响比分的待决事项关闭后，才能发布节结束、终场或加时决定。释放时点在截止前、截止后及数值分辨率边界分别测试。时间容差来自固定步长与事件子时刻分辨率，不能使用任意数秒的统一宽限。

## 3. 数据协议与重建接口

### 3.1 运行与流完整性

新增 `ValidationManifest`：输入包摘要、完整规则与阵容、代码版本及工作区内容摘要、随机算法版本、种子、scope、协议版本、准则集合摘要、参考摘要、数值单位、坐标方向、采样间隔、预算、预期比赛数、认证范围。

流首部声明必需能力；尾部提供终局原因、记录数、事件数、最后 tick、完整性摘要及未完成业务实例数量。缺少尾部属于截断流。每条帧提供 `tick_index`；每个事件采用 `(tick_index, sequence)` 排序，时间显示值不承担身份判断。

`Frames` 与 `FramesGzip` 保留同等证据；`Facts` 保留事件及事件必要的局部几何快照，无法验证连续运动的项目显式未判定；`Summary` 仅可运行已登记的汇总指标。完整认证要求运行中检查全部运动 tick，并保存运动证据摘要与失败区间；独立离线几何复评要求对应完整帧。运行中零违规不能证明未保存的几何已得到离线独立复核。

### 3.2 业务实例与多种关系

在事件信封新增可选业务身份：`action_id`、`shot_id`、`pass_id`、`loose_ball_id`、`foul_program_id`、`responsibility_id`、`movement_intent_id`、`play_instance_id`。适用类型的必填约束由协议注册表规定；同一实例从创建到终结身份不变。

保留 `parent_event_id` 表达直接触发，同时新增 `relations: [{kind, event_id}]`。关系类型包括 `CausedBy`、`CreatedBy`、`InterruptedBy`、`AwardedBy`、`RecoveredFrom`、`Continues`、`InfluencedBy`。关系有类型和基数约束，触发原因指向更早的事件；结束事件引用开始事件，禁止回写开始事件造成环。

- 投篮结果与出手：同一 `shot_id` 与进攻队，允许防守触球作为附加原因。
- 抢断与传球：同一 `pass_id`，抢断人属于对方球队。
- 防守篮板或抢断与转换开始：允许跨回合；新攻方等于取得控制的一方。
- 犯规与罚球：同一 `foul_program_id`，犯规人与罚球人可以属于不同球队；执行人按罚则确定。
- 换防与责任交接：两个责任实例显式关联，参与者、接管对象和生效 tick 明确。
- Play 与动作：动作启动时保存正在生效的影响身份；窗口结束后停止新增影响，但已形成的动作、传球和投篮继续沿业务关系归因，直到实例终结。

合法跨球队与跨回合关系按上述类型验证；无法合法匹配才判缺陷。普通 `SetPlay` 来源不证明存在一个已激活的 `PlaySpec`。

### 3.3 新增观测载荷

- `MovementIntent`：球员、原因事件、任务类型、目标区域、目标对象、起始 tick、计划期限、修订号；修订记录替代关系。
- `MovementOutcome`：完成、被阻断、被中断、超时、被新任务替代及证据；实际轨迹由物理帧提供。
- `ResponsibilityStarted/Ended`：对位或区域、接替人、开始与结束条件、成功或失败；失败是比赛行为记录。
- `PlayWindowEnded`：对应激活身份、结束原因和冷却截止；`DecisionTrace` 记录实际应用的规则和候选增量。
- `ControlEstablished`、`PossessionAwarded`、`ClockChanged`、`PeriodSettlementCompleted`：提供独立球权和时钟重建所需事实。
- `StatAttribution`：引擎输出的记账声明，包含球队、可选球员、来源业务身份、统计种类和规则依据；验证器独立重算后比较。

新增接口以类型化 Rust 数据结构加 `serde` 序列化定义。旧流使用显式版本适配器；无法从旧字段可靠得到的事实不得猜测补全。

## 4. 可执行机会与空间测量

### 4.1 机会生命周期

新增 `OpportunitySpec`：`id`、版本、输入字段、观察频率、进入谓词、退出谓词、最短持续时间、合并间隔、窗口截止、观察对象、测量值、容差出处。所有参数必须有限且单位明确；缺项在运行前拒绝配置。

一次机会以 `(game_id, spec_id, actor_ids, start_tick)` 唯一识别。进入谓词持续达到最短时间后确认机会，起始时间回记首次满足时刻；短暂接触类事件使用即时机会，不套用持续时限。结束由退出谓词、球权改变、判罚、动作结束或比赛范围结束决定。统计每次机会的持续时间及选择次数，不能把每 tick 当独立机会。

对没有独立数据支持的空间阈值，允许作为声明的几何测量协议用于相对机制实验；其绝对频率不得作为真实比赛认证证据。追踪数据必须运行同一测量协议。

### 4.2 空间谓词

**接球窗口**：对规则允许且持球人当时可见的候选目标，计算传球到达时间；接球人从当前状态在速度、加速度与动作限制下能够到达接球区域；沿传球飞行路径计算防守人最早可达时间。记录 `receiver_arrival_margin` 和最小 `defender_intercept_margin`。两者达到测量档案阈值且传球合法时构成可用窗口。使用固定几何候选集和独立可达性计算器，不读取生产候选是否已被选中。

**出手窗口**：持球控制有效、出手合法、当前动作允许完成释放；记录出手区域、最近防守距离、防守可达时间与释放时间差。开放程度按冻结区间分组。评价选择质量必须再考虑能力、时间、比分和其他机会，单个未选择空位不判结构错误。

**掩护与利用**：从掩护动作及几何记录站定、朝向、合法距离和接触条件；无身体接触但迫使防守绕行的情形允许单独登记。利用量为持球人通过掩护侧的路径、相关防守人的绕行长度与恢复防守距离所需时间。滑出单独登记，不要求先完成接触。

**半场组织窗口**：本队已建立前场控制且处于活球，无尚未结束的转换任务；连续时间达到档案阈值。防守是否已到位另作标签，禁止用“防守成功到位”筛选全部样本。转换任务在指定前场组织建立、出手、失误或规则中断时关闭。

**到位与回位**：实际位置进入任务目标区域，满足对象距离或覆盖角度要求并持续指定时间。超时但如实记录失败属于行为样本；声明完成却不满足几何是 `Integrity` 缺陷。协防允许有意放空低威胁对象，该策略及失位结果需要可追溯。

**轨迹测量**：统一换算为英尺和秒；长度为相邻位置距离之和，速度与加速度按相邻真实时间差计算。离散规则放置只豁免明确列出的球员、球和 tick。帧间缺失不得视作连续采样；高速接触用前后状态的连续碰撞证据验证，不能只靠帧端点。

## 5. 准则注册表与五层场景目录

每个编号是稳定准则族。实施时注册为 `family_id/check_name`，每个叶项具备输入、计算函数、机会定义、严重度、退出条件、场景 ID、参考要求及输出 schema。一个叶项只产生一种结论；混合检查必须分别输出。注册表未覆盖下列任一义务时，完整能力建设不能完成。

### 5.1 第 1 层流程目录

- `FLOW-A01`：动作开始后恰有一个终态；窗口按业务身份清算。
- `FLOW-A02`：动作阶段合法；中断只关闭尚可被中断的动作部分，已释放的有效篮球继续结算。
- `FLOW-A03`：覆盖 `JumpShot`、`Layup`、`Dunk`、`PassRelease`、`ScreenSet`、`CloseoutContest`、`ReboundJump`、`ScreenRoll`、`ScreenPop`、`Cut`、`CutBackdoor`、`BoxOut`、`Putback`；每类登记正常、阻断、判罚和回合边界的适用测试。
- `FLOW-A04`：窗口完成、移动到位、接球与投篮结果分别结算，禁止相互替代。
- `FLOW-S01`：每次投篮只有一个最终裁决；普通命中、触筐投失、未触筐投失、触板投失、封盖后继续飞行或争抢、出界和规则无效均有分支。
- `FLOW-S02`：离手前与离手后触球分别验证；合法封盖、干扰球和篮筐干涉按规则区分，更新后的球轨迹只结算一次。
- `FLOW-S03`：投失之后核对控制、出界、争球或判罚；接触事实按实际接触记录，篮板归属由控制建立确定。
- `FLOW-S04`：进攻篮板延续回合；进攻时钟读取触筐与控制条件；防守篮板开启对方进攻。
- `FLOW-S05`：二分未中犯规、三分未中犯规、二分加罚、三分加罚和无效投篮分别核对判罚、得分与投篮记账。
- `FLOW-P01`：传球在接住、截获、出界、规则取消或转为松球时结束原飞行；点球和掉球后的松球实例通过关系继续追踪。
- `FLOW-P02`：冻结目标、实际接球位置及修正事实按 `pass_id` 核对。
- `FLOW-P03`：哨响中断的传球有 `InterruptedBy`，不得自动记为技术失误。
- `FLOW-D01`：突破到达、被阻断、分球、出手、被拨球与判罚都有明确终态；分球无需先出现到达篮下事件。
- `FLOW-L01`：所有松球实例以控制、出界、争球或判罚关闭。
- `FLOW-L02`：暂时无持球者不自动改变统计回合；控制与规则授予共同决定后续。
- `FLOW-R01`：个人、投篮、进攻、松球、技术以及认证联赛要求的其他判罚逐类覆盖；规则依据和队内责任明确。
- `FLOW-R02`：罚球程序保留来源、执行人、尝试序号、重罚与有效次数；末罚是否可争抢、罚球后是否保留球权由罚则决定。
- `FLOW-R03`：发球时限、进攻时限、后场时限、三秒、回场、走步、二次运球、出界、争球等按联赛能力目录逐项检查。未实现的必需规则阻止该联赛完整认证。
- `FLOW-R04`：换人须满足具体的换人许可条件，仅停表不足以证明合法；核对资格、在场人数及板凳耗尽的联赛例外。
- `FLOW-R05`：时钟截止后等待待决投篮和罚则，结算比分后才决定下一节、加时或终场；犯规账期按联赛设置。

全部 `FLOW` 叶项为 `Integrity`，目录覆盖测试计入 `ValidatorImplemented`。真实比赛中动作失败可满足流程检查。

### 5.2 第 2 层事实与账本目录

- `CAUSE-I01`：唯一事件身份、顺序、无环与关系基数；业务实例只结算一次。
- `CAUSE-I02`：突破终结、急停、切入接球、前场篮板、转换与普通组织来源分别核查。一个投篮允许多个维度的来源，主要来源与附加来源分开保存。
- `CAUSE-I03`：按第 3.2 节验证跨回合及跨球队关系，尤其是抢断、防守篮板、犯规和转换。
- `CAUSE-I04`：传球、投篮、动作、罚球程序和控制事实配对完整；多次相同执行人不串配。
- `CAUSE-B01`：独立重建双方及球员 `PTS/FGA/FGM/3PA/3PM/FTA/FTM/ORB/DRB/BLK/STL/TOV/PF`，与引擎统计逐项比较；`AST` 需有经过来源审核的助攻归属事实。
- `CAUSE-B02`：独立球权和规范统计回合与 `PossessionSummary` 比较，附加罚球和球队失误单独处理。
- `CAUSE-B03`：三种时长、时钟运行与重置分别重建，节末待决期间比赛钟为零但物理过程可继续。
- `CAUSE-B04`：个人与球队责任、罚球资格、个人犯规和球队奖励状态独立重算。

全部 `CAUSE` 叶项为 `Integrity`。合法出手或失误的统计判定根据独立规则资料，不能使用当前引擎枚举作为真值。

### 5.3 球员运动目录与级别

以下各族分别注册 `/fact`（`Integrity`）和适用的 `/profile`（`Distribution`）或 `/response`（`Mechanism`）。到位率不足只能影响分布或机制结论。

- `MOVE-H01`：持球人和篮球连续性、速度、加速度、边界、持球合法性。
- `MOVE-H02`：推进和突破的任务、真实轨迹、到达或阻断证据。
- `MOVE-H03`：利用掩护的路线、屏障几何与防守绕行；拒绝掩护也作为合法选择记录。
- `MOVE-H04`：已有机会下停留、出手或传球的采用率，按时钟和比分分组；无单次强制采用要求。
- `MOVE-O01`：切入、背切、转移、定点、掩护、顺下、外弹、卡位与补篮的运动任务和终态。
- `MOVE-O02`：切入接球的窗口、实际控制及身份一致性；切入未接球保留为机会未采用。
- `MOVE-O03`：掩护建立、滑出、提前离开、顺下、外弹与阻断分别测量。
- `MOVE-O04`：冲抢与退防任务分别评价，不能要求全部进攻球员争抢篮板。
- `MOVE-F01`：真实防守距离、可达时间与干扰记录；能力调制和原始几何分列。
- `MOVE-F02`：挤过、绕过、沉退、延误、换防、协防、回位任务与真实运动一致。
- `MOVE-F03`：责任分配、移交与执行成功分别记录；回位缓慢、沟通失败及主动放空属于行为样本，伪报完成才是结构缺陷。
- `MOVE-F04`：抢断、封盖、卡位及篮板控制的几何和接触证据。

### 5.4 战术目录与级别

- `TACT-O01/fact`：槽位指派完整、人员资格合法、换人后引用有效；能力适配采用声明的确定性目标和同分处理。
- `TACT-O02/profile`：半场组织中的队友间距、禁区占用、传球窗口与弱侧空间，测量定义见第 4 节。
- `TACT-O03/profile`：外线展开、高位掩护、切入、低位组织与认证范围内其他体系的机会构成。
- `TACT-O04/response`：固定阵容只改变体系，分别报告空间、机会、选择和结果变化；不要求每个体系都改变全部指标。
- `TACT-P01/fact`：触发谓词、竞争选择、激活窗口、冷却和身份一致。
- `TACT-P02/fact`：有效窗口内施加声明的候选增量与约束；结束后停止新增修正，已启动动作按自身生命周期继续。
- `TACT-P03/fact` 与 `/response`：规则匹配、目标修订、实际跑位、机会和选择逐环节可追溯。
- `TACT-P04/profile`：未能形成掩护、被防守破坏、判罚中断、形成机会后投失分别计数。
- `TACT-F01/fact` 与 `/profile`：同一掩护面对换防、沉退、延误、挤过或绕过，核对责任与条件空间分布。
- `TACT-F02/fact` 与 `/profile`：对位防守和区域防守分别核对对象或区域责任，球转移后的覆盖变化。
- `TACT-F03/profile`：所有认证进攻体系与防守体系按兼容矩阵交叉比较；不兼容组合需静态依据，不能因测试失败排除。
- `TACT-F04/fact` 与 `/response`：教练调整的来源、有效时间及后续实际响应。

`/fact` 为 `Integrity`，`/response` 为 `Mechanism`，`/profile` 为 `Distribution`。局部战术失败不触发结构阻断。

## 6. 第 3 层：数据、指标和确定的统计判定

### 6.1 参考适用范围

`ReferenceManifest` 固定联赛、规则年份、赛事类别、比赛名单、许可证、数据版本与摘要、获取转换程序版本、缺失率、样本选择、坐标映射、统计定义和审核人。使用成熟 JSON、CSV、Parquet 等解析库；数据下载失败或 schema 错误立即报告。

按整场比赛划分参考构建集、方法校准集、封存验收集，同一比赛的球队、回合和帧始终处于同一集合。封存集参与验收后，若据其结果修改模型或阈值，必须登记已使用状态，并取得新的独立验收证据。

`PopulationSpec` 声明模拟阵容集合、阵容抽样权重、对手配对、球员能力映射、战术构成及联赛范围。比较联盟总体需要具有对应代表性的模拟赛程；固定一套阵容只比较相应条件群体。参考条件没有足够重叠时标记 `reference_out_of_scope`，结论为 `InsufficientEvidence`。真实数据没有引擎能力分值时，采用经验证的能力映射或可观测球员角色条件，禁止直接假定同值。

PBP 不能提供未记录的传球次数和连续跑位；空间分布需追踪数据。只得到有限追踪比赛时，认证范围限定到其覆盖的比赛群体。数据缺口仍保留在完整认证的必需清单中。

### 6.2 指标与公式

每个族的叶项登记分子、分母、统计单位、加时政策和零分母处理。零分母为未判定，不填零。

- `STAT-G01`：球队得分、总分、分差；进攻效率 `100 × points / possessions`。附加罚球得分归球队并保留标签。
- `STAT-G02`：球队回合数；NBA Pace 使用 `48 × (home_possessions + away_possessions) / (2 × played_game_minutes)`；其他联赛用其常规比赛分钟数。时长取比赛钟实际运行时长，加时计入分母；同时报告不含加时的常规时间指标。
- `STAT-S01`：`FGM/FGA`、`3PM/3PA`、`3PA/FGA`；四区出手份额与各区 `FGM/FGA`；总命中率采用汇总分子分母，场均命中率分布另列。
- `STAT-S02`：出手来源、转换时间、前场篮板后二次出手时间、防守距离条件下的选择与命中。主要来源份额总和为一，附加标签不要求互斥。
- `STAT-R01`：`FTA/FGA`、`FTM/FTA`、每百回合犯规、投篮犯规占适用犯规比例、奖励阶段罚球；技术罚球单列。
- `STAT-T01`：`TOV/possessions` 和规范失误原因份额；球队失误及过程标签分别展示。
- `STAT-B01`：`ORB/(ORB + opponent_DRB)`，仅包含冻结口径中可争抢的投篮和末罚机会；球队篮板、无争抢统计篮板与无归属情形单列。前场篮板后出手率以已控制前场篮板实例为分母。
- `STAT-P01`：每回合完成传球数、各传球结果占比、突破与切入机会采用率；机会时长也保留。
- `STAT-M01`：轨迹长度、速度分位数、到位时间、队友距离、禁区占用时长、防守距离、协防恢复时间。位置类帧指标按时间加权，再按比赛聚合，禁止把帧视为独立比赛。
- `STAT-I01`：球员比赛钟上场分钟、得分和出手份额、规范使用率、能力或角色条件表现。`AST/FGM` 需要正式助攻记账依据；接球来源率另命名。

四区边界、外线几何、换边方向、节末超远出手和未触筐球的处理在 `MetricSpec` 固定。官方技术统计与从参考 PBP 重建统计不一致的比赛必须查明原因，不能仅删除不利样本。

### 6.3 比较量和等效区间

统一采用“实际差异是否在允许范围内”的等效判定：

- 比例、均值、预登记分位数：统计量为模拟减真实的差值，允许区间为 `[-delta, delta]`。
- 一维完整分布：Wasserstein-1 距离，以实际单位报告，允许区间 `[0, delta_w]`。
- 有限类别构成：Total Variation 距离 `0.5 × sum(abs(p_sim - p_real))`，允许区间 `[0, delta_tv]`。
- 联合关系：预登记二维分箱的类别距离、条件率差或条件分位数差；分箱只由构建集确定。

`delta` 必须在模拟验收前由业务上允许的最小实质差异及参考测量误差登记并审核，记录理由。文档不编造所有指标通用的数值。缺少数值与审核证据的叶项不能进入正式运行配置；这是明确的数据准备任务。

参考与模拟分别以整场比赛作为 cluster 进行 bootstrap，同场双方、全部回合和帧共同抽取；保持预登记的阵容及赛事分层权重。每个批次冻结所有必需统计叶项数量 `m`，采用 Bonferroni 同时置信水平 `1 - 0.05/m`。使用成熟统计库，登记版本、bootstrap 算法与随机种子；重复次数至少满足 `B × 0.05/(2m) >= 100`，同时记录 Monte Carlo 稳定性检查。计算资源不足时未判定，禁止减少检查项后宣称全体通过。

置信区间完全位于允许范围内给 `Pass`；与允许范围无交集给 `Defect`；有交集但未完全包含给 `InsufficientEvidence`。单场位于真实分布尾部仅产生诊断实例，不能按中央分位数范围逐场阻断。

### 6.4 样本量与停止规则

在校准集上按正式群体权重抽取两组真实比赛，执行完整判定方法，检查同源数据的误报率。用预登记的概率重加权得到距离在边界外的参考分布，计算检出率；该分析只用于方法校准，保留来源标识，不作为引擎比赛。

选择满足对预登记的实质超限替代分布检出率至少 0.8、族级误报率不超过 0.05、关键差值区间宽度不超过对应容许宽度一半的最小比赛规模；替代分布的超限距离必须固定，不能要求检测任意接近边界的差异；固定 `n_games`、各条件最小事件量及最大资源预算。参考数据规模不足以支持该评估时，认证被数据依赖阻塞。正式批次不进行反复查看后提前停止，也不以新种子替换失败比赛。需增加样本时预登记新批次，报告全部批次。

## 7. 第 4 层：直接机制与完整比赛反馈

### 7.1 直接机制实验

从真实引擎运行保存决策前检查点，包括球态、动作、位置、体力、时钟、规则、战术及随机状态。检查点集合在查看扰动结果前冻结。恢复后只修改目标输入并通过生产初始化逻辑更新其派生量，完整验证状态一致性。

每次实验使用低、中、高三个合法水平，登记确有单调语义的观测量。例如固定出手条件下的精度、固定冲刺任务下到位时间、固定罚球程序中的成功率。反复执行真实生产路径，不覆写命中或行为结果。对受输入影响的机会数和采用率，以全部冻结检查点为分母，不只筛选扰动后成功出手的样本。

随机机会需要配对时新增具名随机键 `(experiment_id, checkpoint_id, subsystem, trial_id, draw_index)`；相同意义的抽样才共享键。运行前检查键的含义和次数，分支新增抽样使用独立键。普通相同 seed 只提供可复现性，不承诺逐动作随机值配对。

### 7.2 全场反馈实验

固定赛程、阵容配对及其他参数，每次只改变一个输入，完整运行每场。以比赛为配对单位，计算机会数、动作数、条件结果及全队输出的差值区间；记录对手响应和选择构成变化。正式检验使用全部比赛的总效应。扰动后才出现的机会子集只作为解释信息，不能用其条件命中率证明直接因果效应。

直接效应的方向门要求置信区间超出事前定义的最小效果；不应变化的量用等效区间检查。全场指标仅对有明确依据的方向设门；其余报告效果及分布真实性。采用第 6 节的多重比较与样本计划。

### 7.3 输入覆盖目录

每个输入建立直接机制叶项与全场反馈叶项，并记录预期受影响的通道：

- `MECH-S01`：`shooting_close`、`shooting_near`、`shooting_mid`、`shooting_three` 的区域精度与选择。
- `MECH-S02`：`finishing`、`vertical`、`block` 的终结、接触高度、合法触球与结果。
- `MECH-P01`：`passing`、`ball_handling` 的传球执行、接球和控制丧失。
- `MECH-M01`：`speed`、`acceleration`、`agility`、`off_ball_sense`、`stamina` 的运动、感知、体能消耗与恢复。
- `MECH-B01`：`strength`、`offensive_rebound`、`defensive_rebound` 的对抗与篮板控制。
- `MECH-F01`：`defense_perimeter`、`defense_interior`、`steal`、`help_aggressiveness`、`gamble_steal`、`physicality` 的防守机会、选择及代价。
- `MECH-R01`：`free_throw`、`decision_iq` 的罚球与固定信息下的决策质量。
- `MECH-T01`：`shoot_frequency`、`drive_frequency`、`pass_frequency`、`cut_frequency`、`screen_frequency`、`offensive_rebound_frequency`、`block_aggressiveness`、`risk_tolerance`、`transition_sprint` 的倾向采用率。
- `MECH-T02`：体系、Play、所有战术谓词、动词、候选增量和抑制的实际消费及结果。
- `MECH-C01`：球队 `pace`、`three_point_emphasis`、`rim_pressure`、`defense_aggression`、`rebound_emphasis` 与教练、轮换输入的响应。

全部属性和档案字段用 schema 枚举检查覆盖；新增字段没有实验登记即测试失败。合法中性参数作为对照，运行真实消费路径，不替换生产函数。目标参数本就处于饱和区的场景不用于证明全域无响应；登记边界、中段及交互场景。

## 8. 第 5 层：联合与连续过程

联合准则的分组由构建集固定，采用与模拟一致的机会提取器；时间顺序及跨回合关系保留。默认全部下列族为认证必需，缺少追踪数据保持未判定，不得改名为诊断以获得通过。

- `JOINT-C01`：球队比分差、比赛剩余时间与进攻时钟共同条件下的节奏、出手、犯规战术及轮换。
- `JOINT-C02`：阵地、篮板转换、抢断转换、松球转换各自的推进和回防人数、第一出手时间及结果。
- `JOINT-C03`：突破、外线空间、协防与传球出口；掩护、顺下、弱侧转移与对应防守的联合分布。
- `JOINT-C04`：出手位置、真实球运动、卡位、冲抢或退防与前场篮板后二次进攻。
- `JOINT-C05`：犯规账期、奖励状态、对抗选择及罚球；控制时间与阵容等共同条件。
- `JOINT-T01`：进攻体系与防守方案的全体兼容组合，比较有足够资料支持的条件指标。
- `JOINT-T02`：Play 激活、机会生成、采用、结果及中断类型；已经开始的业务实例在窗口外终结时仍沿冻结的来源关系归因。
- `JOINT-I01`：球员能力映射、使用机会、上场时间、队友和对手之间的关系，以及换人后的空间和体力变化。
- `JOINT-Q01`：连续回合的得分、时长、失误与动作类别转移矩阵，预登记 lag-1/lag-2 条件统计；暂停、换人、战术变化前后按相同状态条件比较。连续命中后的条件相关可测量，未经识别的“热手原因”只登记 `Diagnostic`，不据相关性宣称因果。

失败实例按固定抽样规则导出，同时包括普通通过样本，防止只观察极端回合。片段解释只能提出原因候选；机制归因必须有第 7 节实验支持。

## 9. 可复现的场景用例

### 9.1 场景 schema 与执行

`ScenarioSpec` 必填：ID、规则版本、`MatchSetup` 或检查点摘要、前置状态断言、目标触发、允许分支、必需事实、禁止事实、比较的统计增量、最大 tick、固定 trial 集合、目标准则和证据输出模式。

入口有完整比赛、生产路径检查点恢复和声明式合法初始状态三种。状态构造器校验球员资格、人数、控制、时钟、待决动作及判罚，并使用生产的状态初始化程序；不能直接填入希望得到的结果。检查点保存所有派生状态的重建信息。设定种子仅用于复现，不能在失败后搜索新种子替换。

规则程序的定向测试在达到触发前置状态后执行正常裁决；概率行为使用预登记 trials，按声明的分支覆盖和概率判据验收。超出预算未触发必需分支为场景覆盖失败。场景开始时前置条件不成立属于输入错误。自然比赛零机会仅记录零覆盖，不影响定向测试的必须触发要求。

### 9.2 必需案例

每行均生成具体 `ScenarioSpec`；所述状态通过合法构造或冻结检查点得到。

| 场景 | 前置状态和变化 | 允许过程与必查结果 | 失败例 |
| --- | --- | --- | --- |
| `SC-SHOT-OPEN` | 固定持球位置与远处防守人；对照缩短防守距离 | 正常生产决策和投篮；几何、选择、命中分别测量 | 一次不中就判缺陷 |
| `SC-BLOCK-BEFORE` | 投篮动作中、离手前存在合法触球机会 | 记录触球阶段和统计裁决；球随后争抢 | 强制全部记为失误 |
| `SC-BLOCK-AFTER` | 已离手且球在合法可封盖状态 | 球运动更新、唯一终局、正确出手和封盖记账 | 原轨迹继续重复得分 |
| `SC-AIRBALL` | 合法出手、无触筐接触 | 可控制或出界；时钟依据触筐状态处理 | 无接触却重置进攻时钟 |
| `SC-REBOUND` | 同一类投失，控制者分别为双方 | 前场续回合、后场易主；多次前场篮板仍一条进攻链 | 每次松球增加回合 |
| `SC-PASS-REPEAT` | 同一对球员连续传球，第一次被点球后重新控制 | 按 `pass_id` 配对各自终局 | 后一次接球匹配前次传球 |
| `SC-PASS-WHISTLE` | 传球飞行中发生合法判罚 | 原传球中断并保留原因；记账按规则 | 中断自动增加失误 |
| `SC-DRIVE` | 相同突破起点，通路、防守阻断与协防分别变化 | 到达、分球、急停、中断等按实际事实结算 | 到达窗口直接计分 |
| `SC-SHOOTING-FOUL` | 二分或三分出手的合法投篮犯规 | 四种命中或未中组合的得分、罚球及 FGA 口径 | 所有情境统一罚两次 |
| `SC-TECHNICAL` | 有效进攻中追加技术判罚 | 得分与原球权按规则处理 | 附加罚球建立普通新回合 |
| `SC-FT-PROGRAM` | 非末罚、末罚及保留球权罚则分别执行 | 命中、投失、重罚、球权和来源序号正确 | 非末罚投失启动篮板 |
| `SC-CLOCK` | 各时限前一个 tick、边界、后一个 tick | 触发条件、计时暂停和重置符合规则 | 固定宽限吞掉违例 |
| `SC-BUZZER` | 截止前离手，球在时钟归零后继续飞行 | 先结算投篮与罚则再决定终场或加时 | 未结算就宣布胜负 |
| `SC-TEAM-TOV` | 规则定义为球队责任的违例 | 球队 TOV 增加，个人 TOV 按规则保持 | 随意指定持球人为责任人 |
| `SC-SUBSTITUTION` | 合法窗口、非法窗口、犯满和无可用替补 | 资格与许可判断、人数、槽位更新 | 只凭停表允许换人 |
| `SC-MOVEMENT` | 三类球员分别执行冲刺、切入、追防及阻断 | 意图、连续轨迹、到位或如实失败 | 有目标点就声明已到位 |
| `SC-SCREEN` | 站定掩护、滑出、移动接触、未接触绕行 | 分别核对合法性、路线和机会 | 所有情况要求先有接触 |
| `SC-COVERAGE` | 同一进攻分别面对换防、沉退、延误、绕过和挤过 | 责任移交、真实轨迹及条件机会 | 漏人行为全部当结构错误 |
| `SC-ZONE` | 采用区域责任，球由一侧传向另一侧 | 覆盖区域随球和威胁变化，允许真实失位 | 只验证平均距篮距离 |
| `SC-PLAY-END` | 窗口内启动传球或投篮，窗口外完成 | 停止新修正；保留既有因果归属 | 到窗口截止即删除父链 |
| `SC-PLAY-COMPETE` | 多 Play 同时满足、冷却及回合终止 | 按选择规则只激活允许数量，状态可重建 | 冷却期间重复激活 |
| `SC-TRANSITION` | 篮板或抢断后新攻方建立控制 | 允许跨回合关系，核对双方转换跑位 | 因跨球队父链误报 |

认证联赛的额外判罚、争球与规则边界从 `BasketballRuleProfile` 自动列入场景覆盖要求，不能只依赖表内常见案例。

### 9.3 验证器自身检查

正向样本来自可重放生产运行、独立来源真实记录及其正式适配器。解析器使用真实输入的截断、缺失文件和版本不兼容测试明确拒绝行为；损坏字节不作为比赛记录参与真实性统计。统计算法使用数学上已知的边界性质和成熟库的标准测试。

对验证器修改采用保存的真实缺陷运行记录回归，验证它能报告已知错误，并在合法场景不误报。机制实验使用合法中性配置作为对照；不得使用 mock、覆写生产结果或伪造比赛事件来取得验收通过。

## 10. 软件边界、资源与工件

新增纯读取的 `ObservationReader`、`SemanticReconstructor`、`OpportunityExtractor`、`MetricAccumulator`、`StatisticalComparator` 和 `GateEvaluator`；名称为目标接口。模拟器只输出事实，比较器不能反向影响生成过程。规则判定器、机会提取器和指标计算器共享同一规范输入层，真实数据适配器与模拟适配器分别实现。

逐场流式处理；内存只保存进行中实例、必要历史窗口与索引缓存。完成实例和跨回合关系索引写入项目下受忽略的运行目录，使用 SQLite 等成熟存储库查询；完整帧采用分块压缩并建立 tick 索引。空间检测读取连续帧，聚合统计保存每场充分统计量；bootstrap 处理比赛级记录。资源上限在 manifest 显式配置，超限返回执行错误，不能截掉比赛尾部。

新增输出：`validation_manifest.json`、`coverage.json`、`instance_judgments.ndjson`、`ledger_comparison.json`、`game_metrics.parquet`、`statistical_results.json`、`mechanism_results.json`、`scenario_results.json`、`validation_report.json` 及失败片段索引。旧 `judgments.ndjson` 与 `attribution_report.json` 由同一裁决生成兼容视图，禁止维护第二套判据。

每条裁决包含：`criterion_id`、版本、`gate_class`、`verdict`、原因码、`opportunity_id`、业务身份、证据事件、帧区间、输入与参考摘要、统计量和区间。UI 只读取结果，可按层、球队、球员、战术、情境和事件定位；不得在 UI 内重新判断是否通过。

CLI 提供运行场景、采集比赛、离线评判、构建参考和执行实验的独立命令接口。退出码：`0` 所请求认证全部通过；`1` 有确定缺陷；`2` 输入或执行错误；`3` 必需证据不足。若同时存在缺陷与未判定，报告两者且返回 `1`；执行错误优先返回 `2`。

## 11. 必需覆盖和实施依赖

以下清单决定完整能力的范围；不能由实施者自行删减必需项目。

| 工作包 | 必需内容 | 完成证据 | 依赖 |
| --- | --- | --- | --- |
| `validation_semantics` | 第 2 节全部规则、统计映射、来源审核 | approved 档案和独立案例；待审核项为阻塞 | 联赛及统计资料 |
| `validation_protocol` | 第 3 节实例、关系、时钟、尾部和能力声明 | schema、版本适配、完整性测试 | 语义 |
| `validation_reconstruction` | 全部 FLOW、CAUSE 叶项 | 独立重建和第 9 节结构场景通过 | 协议 |
| `validation_movement` | 全部 MOVE、空间机会与连续几何 | 三类球员场景、事实检查、测量协议 | 协议、空间证据 |
| `validation_tactics` | 全部 TACT 叶项和兼容矩阵 | 档案字段覆盖、跑位、Play 生命周期 | 重建、运动 |
| `validation_reference` | 全部 STAT、JOINT 的数据适用与统计配置 | 独立来源、数值容限审核、方法校准 | 语义、真实数据 |
| `validation_mechanisms` | 全部 MECH、所有公开能力倾向与战术字段 | 检查点、具名随机、直接与全场实验 | 重建、运动、战术 |
| `validation_joint` | 全部 JOINT 条件及序列项 | 条件样本充分、正式等效判定 | 参考、机会提取 |
| `validation_delivery` | 严格 CLI、工件、UI 消费、CI、预算 | 离线一致性、错误传播与完整批次 | 以上各项 |

完整建设要求这些工作包都达到 `ValidatorImplemented`。真实数据尚未取得的项目必须明确列出负责人角色、所需字段、数据许可及获取任务，并阻止 `RealismValidated`；不能用实现完成代替外部证据完成。

所有 FLOW、CAUSE、MOVE 的 `/fact`、TACT 的 `/fact` 和第 9 节适用场景为结构必需；所有公开输入对应的 MECH 为机制必需；STAT 全部族和 JOINT 全部族的登记叶项为真实性必需。研究性的因果解释仅列 `Diagnostic`，不得计入覆盖分子。

开发 CI 运行全部确定性场景、协议和重建测试及冻结回归比赛；正式认证运行冻结完整赛程、全部机制实验、参考比较和联合检查。二者报告不同范围，不以开发 CI 通过替代正式认证。文档测试核对编号唯一、目录到叶项覆盖、字段和依赖完整；算法测试核对公式、阈值边界和四态；集成测试使用真实引擎；正式验收保留所有输入、工件和可复现命令。
