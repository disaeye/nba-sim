## 0. 文档目的

本文档回答三个问题：

1. **按什么顺序做** —— 里程碑 M1–M10 的依赖与顺序（§1）；
2. **如何安全地校准** —— 校准协议：参数必须走什么通道、改默认值要附什么证据（§2）；
3. **每步验收什么** —— 里程碑验收标准与持续质量门（§3）。

阅读顺序：§1（里程碑）→ §2（校准协议）→ §3（验收标准）。

## 1. 里程碑（M1–M10）

### 1.1 阶段划分

| 阶段 | 内容 | 风险 | 依赖 |
|------|------|------|------|
| **M1 不变量内建** | `crates/invariants` + step 包装 + 导出报告 + violations 工件 + severity 分级 | 低 | 无 |
| **M3 确定性基线** | 黄金 tick 哈希 + 阶段门统计基线 + **CI 化** | 低 | M1 |
| **M7 参数收编** | 子系统内联常量 → `GameRules`/`DecisionRules`；`officiating/config.rs` 并轨；audit_stream.py 退役 | 中（行为必须逐批保持，黄金哈希锁） | M3 |
| **M8 真实度评判体系（吸收原 M6）** | quality.md §2.1–2.4：回合/阶段评判准则 + 参考分布 fixture + 归因账本 + 工件落盘；原 M6 的叙事校验与统计门 CI 并入（统计门降级为 sanity net） | 中 | M3 |
| **M2 BallState 收敛** | architecture.md §3：领域 BallState 枚举 + 纯函数转换表 + 派生视图替换 | 高（触碰多路径） | M1 |
| **M4 主循环阶段化** | architecture.md §4：管线 + World 拆分 | 高 | M2、M3 |
| **M5 执行重校验** | architecture.md §5.2：意图落地重校验 | 中 | M2 |
| **M9 能力模型与涌现耦合** | quality.md §6：能力→行为端到端耦合、清除常数短路、能力扰动测试进 CI（含负面对照）；前置：`docs/attributes.md` 迁移路线 T1–T3（T1 分类学、T2 映射层、T3 锚点——死维度窗口期换轴先行；T4 罚球接线为 M9 首批接线项；T5 为 M9 验收构成；T6 展示面投影为纯派生层不属引擎耦合） | 高（行为大幅变化） | M7、M8、attributes.md T1–T3 |
| **M10 LeagueProfile 与多联赛** | architecture.md §6.3：档案类型抽出、语义/裁决档案化、FIBA 档案验收场次 | 中 | M7、M8 |

> 顺序原则：**检测网（M1/M3）→ 校准通道（M7）→ 评判闭环（M8）→ 高风险重构（M2/M4/M5）→ 涌现与多联赛（M9/M10）**。理由：(1) 当前最大瓶颈不是代码结构而是缺少真实度反馈信号——没有通道（M7）和评判器（M8），校准无从闭环，引擎能力无法提升；(2) M2/M4 是行为中性重构，先有评判闭环，重构除黄金哈希外还有"真实度保持"这第二验收维度。

### 1.2 里程碑依赖图

```
M1 不变量内建
  └─► M3 确定性基线
        ├─► M7 参数收编 ──┐
        └─► M8 评判体系 ──┼─► M9 能力涌现耦合
                          └─► M10 多联赛
        └─► M2 BallState 收敛
              ├─► M4 主循环阶段化
              └─► M5 执行重校验
```

## 2. 校准协议（血的教训成文）

**前置**：本协议依赖 §3.3 工具链验收中的 `--seeds`/`--out`/batch 违规工件；在其落地前，协议按 status.md §5.1 的当前等价命令执行（跑批为 `--batch N`，种子固定 `1..=N`，聚合打印到 stdout）。

**谁可以改 `GameRules` 默认值？** 任何人，但必须走完整协议，缺一即打回：

1. **先跑基线**：改动前跑批记录统计快照（进 PR 描述）。当前命令：`nba-sim --batch 8 [scope]`（种子固定 1..=8）；目标形态落地后改用 `--seeds 0..7`（quality.md §3.1）；
2. **通道合法**：探参数用 `--rules override.json`（P6），确定值后才进 `rules.rs` 默认值——**禁止"改默认值→重编译→单场目测"循环**；
3. **证据齐全**：PR 必须含 改动前后统计对比（≥8 种子）、归因报告 diff（真实度指数与 top 缺陷准则收缩，quality.md §2.3/§3.5；M8 落地后为必需证据）、落入哪个阶段门（quality.md §2.5）、黄金哈希重冻结 + 一行改动说明；
4. **单一职责**：校准 PR 不得混入行为/重构/性能改动；反之亦然；
5. **门推进**：统计持续逼近下一阶段门时，允许在同一 PR 推进门并注明依据；
6. **新公式纪律**：新决策公式/约束公式的所有系数必须先进 `GameRules`/`DecisionRules` 再写公式。**PR 中出现新的内联浮点行为常数 = 打回**。

## 3. 验收标准

### 3.1 功能验收（每阶段必须满足）

**M1 不变量内建**
- [ ] 每 tick 输出后自动执行全部 L1 规则；
- [ ] 违反时 `ExportSummary.violations` 非空，CLI 退出码为 1；
- [ ] 每条违反携带 `tick_index` + 规则 ID + **severity** + 可读描述；
- [ ] violations 落盘 `violations.ndjson`；
- [ ] 负面对照：注入两人持球/球人分离/比分倒退等场景必须全部捕获；
- [ ] 标准种子跑 1 节，零 Hard 违反（基线）。

**M2 BallState 收敛**
- [ ] 领域层存在 `BallState` 枚举，归属语义不再住在 physics；
- [ ] `BallState` 仅能被纯函数 `transition_ball_state` 写入（grep 无其他赋值）；
- [ ] `carrier_idx` / `has_ball` / `possession` 全部降级为派生只读；
- [ ] 状态转换表穷举测试：所有非法边被拒绝；
- [ ] 标准种子 + ≥5 额外种子全场，`BALL_*` 不变量零违反。

**M3 确定性基线**
- [ ] 相同种子两次运行，逐 tick 哈希完全一致；
- [ ] 黄金哈希入库且 **CI 上永远绿**（红的基线 = 关闭的检测网）；
- [ ] 统计基线为**目标带 + 阶段门**结构（quality.md §2.5），含投篮分解；
- [ ] 种子矩阵（≥ 20 场）批量统计可生成。

**M4 主循环阶段化**
- [ ] `step()` 主体 < 100 行，仅做阶段列表调度；
- [ ] 每个 Phase 有独立单元测试；
- [ ] InvariantPhase 在列表末端，无路径可绕过；
- [ ] 重构后黄金哈希与重构前一致（行为不变）。

**M5 执行重校验**
- [ ] 决策意图落地前重新过硬约束；
- [ ] 世界已变时动作被降级/取消而非强行执行，且记入 trace；
- [ ] 回合评判中"落地改变"率可统计。

**M8 真实度评判体系（吸收原 M6）**
- [ ] 每个回合结束产出 `PossessionVerdict`（结构因果 + 真实度清单两类准则，quality.md §2.1），回合零遗漏；原 M6 的"每回合产出 `PossessionSummary` 且通过叙事校验"并入本项；
- [ ] 每次阶段转换产出裁决（quality.md §2.2）；
- [ ] 参考分布为带版本号的数据档案，不在评判代码中硬编码（quality.md §2.4）；
- [ ] `judgments.ndjson` + 归因报告落盘，batch 模式与 violations 同落；
- [ ] 统计门 CI 化（已降级为 sanity net，quality.md §2.5），含三分命中率 30–40% 目标带（原 M6 验收项）。

**M7 参数收编**
- [ ] 子系统 src 非测试代码内联浮点行为常数 ≤ 20 处（现状 ~734，status.md §1.1 R5；court 几何、单位换算等真常数除外）；
- [ ] `officiating/config.rs` 并入 `GameRules` 体系或成为其子结构；
- [ ] `audit_stream.py` 限值副本删除，审计由 Rust 工具承担；
- [ ] 每一批收编黄金哈希不变或按协议重冻结。

**M9 能力模型与涌现耦合**
- [ ] decision/physics/officiating 的行为权重全部可从 `(能力, 规则, 状态)` 派生，不存在与能力无关的行为常数（quality.md §6、architecture.md §5.1）；
- [ ] 能力扰动测试进 CI：每个能力维度至少一条可观测的单调行为响应链；
- [ ] 扰动测试含负面对照：故意断路一条能力链，测试必须红。

**M10 LeagueProfile 与多联赛**
- [ ] `LeagueProfile` 独立类型：计时结构、进攻时钟与重置、犯规政策与 bonus、几何、语义阈值（architecture.md §6.3）；
- [ ] 现有 `GameRules` NBA 默认值成为 LeagueProfile 的一个实例，引擎代码路径无联赛特化分支；
- [ ] semantics/officiating 为 `f(事实, profile)` 纯函数；
- [ ] FIBA 档案（4×10min、三分线 6.75m、5 犯、单节 bonus）完成一场零 L1 违反且评判工件完整的比赛。

### 3.2 质量验收（持续）

| 指标 | 阈值 | 检测 |
|------|------|------|
| L1 硬违反 | 0 / 全场 | 不变量系统 |
| 两人持球/空气球 | 0 | BALL_* 规则 |
| 比分倒退/时钟回流 | 0 | SCORE/CLOCK 规则 |
| 决策 trace 覆盖率 | 100% | 回合评判前提（quality.md §2.1） |
| 评判工件覆盖 | 回合/阶段裁决零遗漏 | 评判器（quality.md §2.1–2.3） |
| 真实度缺陷 | top 准则违反率连续两轮校准循环收缩 | 归因账本（quality.md §2.3） |
| 能力扰动响应 | 每个能力维度 ≥1 条响应链 | 扰动测试（quality.md §6，M9） |
| 相同种子确定性 | 逐 tick 完全一致 | 黄金哈希 |
| 全场总分（两队和） | [190, 270]（终态目标带；sanity net，非真实度裁决） | 阶段门（quality.md §2.5） |
| 三分命中率 | 30%–40%（sanity net） | 阶段门（先补采集） |
| 回合平均时长 | 14–22 秒（sanity net） | 阶段门 |
| release 吞吐 | ≥ 20,000 ticks/s | quality.md §4 基准 |

### 3.3 架构与工具链验收

- [ ] `domain` 无任何对上层 crate 的依赖（`cargo tree` 验证）；
- [ ] 子系统无反向依赖（physics 不知 decision，semantics 不知 officiating）；
- [ ] 所有魔法数字可在 `GameRules` 中找到，无散落硬编码（≤20 处豁免清单）；
- [ ] 引擎代码路径零联赛特化分支（grep 联赛特化常数/分支，宪章 C3）；
- [ ] 新增一条 L1 规则只需在 `invariants` crate 加一个函数，不改动引擎；
- [ ] 新增内联浮点行为常数的 PR 被守卫实际拦截过（负面对照，宪章 C1）；
- [ ] batch CLI / violations 工件 / 评判工件 / CI 四件套存在并绿。

### 3.4 工具链验收

- [ ] `nba-sim --rules X --seeds A..B batch --out Y` 可用且 release 模式；
- [ ] violations.ndjson 工件由 CLI/引擎导出；
- [ ] 评判工件（`judgments.ndjson` + `attribution_report.json`）由评判器导出，batch 与 violations 同落盘（quality.md §2.3/§3.5）；
- [ ] `.github/workflows/ci.yml`：build + test（含黄金哈希）+ 阶段门统计（缩减种子集）；
- [ ] audit_stream.py 的限值常量删除或脚本退役。
- [ ] `scripts/check_doc_refs.py`（文档交叉引用守卫）在 CI 绿。

## 4. 校准闭环（宪章 C2 的执行主体）

```
跑（批量，quality.md §3.1）
  → 评（逐阶段/逐回合评判，quality.md §2.1–2.2）
  → 归因（缺陷账本：准则 × 子系统，quality.md §2.3）
  → 调（只走 GameRules/LeagueProfile/能力数据/参考分布通道，P6 + C1）
  → 验（sanity net quality.md §2.5 + 缺陷收缩 + 黄金哈希重冻结，quality.md §5）
  → 存（协议证据进 PR，§2）
```

规则：

1. 所有物理/概率/行为参数可从规则体系注入（含 `--rules` JSON 覆盖）；参考分布与联赛档案走同一通道；
2. **校准选题来自归因账本**（频次最高的缺陷准则），不来自直觉；
3. 校准结果由**缺陷收缩**（逐回合裁决，主要）与 **sanity net**（聚合，粗筛）判定，次序不可颠倒；
4. 行为级改动（能力耦合、新公式）同样走本循环——无评判证据的行为改动 = 裸调，与"改默认值→重编译→单场目测"同罪。

## 5. 与其他文档的关系

- `charter.md`（v1.0 立宪）是**目标宪章**：要做出什么、什么算好、红线与成功判据。本文档是**执行路线**：按什么顺序做、每步验收什么；
- `architecture.md` / `quality.md` 是**设计契约**：系统如何组织、如何观测与评判——本文档的里程碑引用它们的章节作为验收内容；
- `attributes.md` / `tactics.md` 是**数据契约**：球员/阵容/战术的分类学与值语义——M9/M10 的前置依赖；
- `status.md` 是**现状与差距**：本文档的里程碑完成度镜像——每次里程碑推进，更新 status.md §4。

## 6. 术语表

| 术语 | 定义 |
|------|------|
| **黄金哈希** | 标准种子逐 tick 关键字段的串联哈希，用于确定性回归 |
| **阶段门 (Stage Gate)** | 校准期间允许统计分布停留的走廊，随进展逐级收窄至目标带 |
| **校准协议** | 修改任何影响行为的默认值必须满足的流程（§2） |
| **归因账本** | 评判缺陷条目按 (准则 × 子系统) 聚合的清单，校准选题的输入（quality.md §2.3） |
| **真实度指数** | 逐回合/逐阶段裁决结果的聚合（不是原始结果的聚合，quality.md §2.3） |
| **能力扰动测试** | 扰动单维能力并要求行为单调响应的测试，涌现的机械守卫（quality.md §6） |
| **sanity net** | 聚合统计的阶段门，只粗筛"错得离谱"，不是真实度裁决（quality.md §2.5） |
