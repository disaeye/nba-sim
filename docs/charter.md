## 1. 这个引擎是什么

一个**硬核篮球比赛模拟引擎**：过程模拟优先，不是玩法优先。

- 给定两队球员与一套联赛规则，引擎从跳球到终场**逐 tick 推演**一整场比赛：跑位、传导、突破、出手、对抗、吹罚、节奏与时间；
- 产物是**比赛过程本身**（事件流 + 逐 tick 帧），比分只是过程的副产品；
- 服务对象：篮球过程研究、战术/规则对比分析、回放可视化、以及引擎自身的真实度评估。

角色边界：

- `cli` / `debug-server` / `bball-wasm` 是**只读观察者**（快照消费 + 生命周期命令），不拥有比赛真相；真相唯一属于引擎（`architecture.md` §1.2）；
- 引擎不做实时人机对抗操作——它是模拟器，不是游戏客户端。

## 2. 范围声明

**在范围内：**

- 单场完整比赛模拟（跳球 → 常规节 → 必要时加时 → 终场）；
- 首个规则集为 NBA，**FIBA、NCAA 在路线图内**（§7），架构从一开始就为多联赛预留；
- 逐回合、逐阶段的真实性评判与缺陷归因（§6）；
- 确定性回放：任何一场比赛可由种子完整复现。

**明确排除（不做）：**

- 球员成长 / 选秀 / 交易 / 薪资等联赛经营；
- 多人在线与实时对战；
- 玩家临场指挥（暂停战术选择、手动操控球员）；
- 商业授权数据分发。

排除项不是"以后再说"的委婉说法：任何把它们带入引擎的提案必须先修订本宪章。

## 3. 目标层级

| 目标 | 一句话 | 地位 |
|------|--------|------|
| **O1 真实** | 懂球的观察者无法从**过程与结果**上区分模拟比赛与真实比赛 | 北极星，其余目标都为它服务 |
| **O2 干净的框架** | 引擎代码无硬编码行为、无上帝函数、状态有单一事实源 | 真实的必要条件（§5） |
| **O3 可配置** | 一套引擎内核 + 多联赛规则档案（NBA/FIBA/NCAA…） | 真实的扩展面（§7） |
| **O4 可评判** | 每个回合、每个阶段都有裁决；每个缺陷可归因到子系统 | 真实的反馈环（§6） |

O1 不可直接验收（"像不像"是主观的），所以它被分解为 O2/O3/O4 三个可机械验收的目标——**逼近 O1 的唯一合法路径是把 O2/O3/O4 做实**。

## 4. 宪章条款（红线）

以下条款是不可触碰的红线。违反任一条的改动 = 打回，无论其动机多好。每条附机械守卫——红线没有守卫就只是愿望。

### C1 · 无硬编码

- **数值层**：一切影响行为的数字必经规则/数据通道（`GameRules` 及其嵌套组、球员/球队数据档案）；子系统源码中不得出现行为常数；
- **行为层**：一切场上行为——谁出手、传给谁、往哪跑、怎么防——必须是 `(球员能力, 规则, 比赛状态)` 的**纯函数**。**禁止剧本化战术**（预编排的回合脚本）、禁止"为了让画面像篮球"而写的经验常数；
- **守卫**：内联常数 grep 守卫（验收阈值见 `design.md` §3.1 M7）；能力扰动测试（§5、`quality.md` §6）——扰动能力而行为不动，即证明存在隐藏脚本或死权重。

> 真实性不能靠抄写真实比赛的片段获得。抄来的行为上限是脚本作者的认知；涌现的行为上限才是球员能力的真实投影。

### C2 · 评判必须落地到每一个回合、每一个阶段

- 比赛是否真实，**必须逐回合、逐阶段地评判**：每个回合结束时有裁决（结构、节奏、出手质量、因果链），每个阶段转换有合法性判定；
- **禁止**以"跑 N 场后对原始结果做指标统计"作为真实性的评判依据。总分、命中率这类聚合量只能当 sanity net（粗筛"错得离谱"），**不是真实度裁决**——正确的总分可以由无数种错误的过程拼出来；
- 允许的是：把**逐回合的评判结果**聚合成比赛级真实度指数。聚合的对象是"裁决"，不是"原始结果"；
- **守卫**：评判工件逐回合落盘（`quality.md` §2.1–2.3）；没有回合级裁决的"真实性结论"在协议上无效。

### C3 · 约束分轴：物理严格、语义灵活

- **物理约束**（人体运动极限、球飞行与碰撞、空间几何）必须严格遵守——这是"物理不可能"检测的依据；它们全局可配置（校准），但**与联赛无关**；
- **语义/规则约束**（计时结构、犯规政策、罚球与 bonus、三分线、跳球与交替拥有、违例判罚尺度）必须按**联赛档案（LeagueProfile）**参数化，灵活可配置——NBA、FIBA、NCAA 规则有出入，引擎内核不为任何一个联赛写死；
- **守卫**：切换联赛只允许通过切换规则档案（数据）完成；为某个联赛修改引擎代码路径 = 违反本条（`architecture.md` §6.3 验收）。

### C4 · 确定性是一切评判的前提

- 相同种子必须产生**逐 tick 完全相同**的比赛；
- 没有确定性，逐回合评判无法复现、缺陷无法归因、校准无法对比、黄金哈希失去意义；
- **守卫**：黄金 tick 哈希入库且 CI 永远绿（`quality.md` §5）。

## 5. 能力涌现：真实性的基石

**论点**：模拟与真实比赛相去甚远的根本原因之一，是行为来自"写死的套路"而非"能力的碰撞"。真实比赛没有剧本——每个动作都是球员能力在当下局势中的表达。引擎必须复现这个因果结构：

```
球员能力向量 ──┐
联赛规则档案 ──┼──► 行为（纯函数，无剧本、无经验常数）──► 比赛过程
比赛状态快照 ──┘
```

**现状基线（2026-09-01）**：`domain/data.rs` 已有 18 维 `PlayerAttributes`（速度/加速/敏捷/力量/耐力/运控/传球/三区投篮/终结/两项防守/抢断/封盖/篮板/球商/站位）+ `PlayerTendencies` + `PlayerRole` + `TeamTraits`，并被 decision/physics/officiating 消费——**能力的载体已存在**；但"行为是否真由能力涌现"没有被验证过，权重链条中仍有大量内联常数短路了能力输入（`status.md` §1.1 R5）。

**推论**：

1. 能力是行为差异的**唯一合法来源**。同规则同状态下，两个球员行为的差异只能来自能力向量与倾向；
2. **能力扰动测试**：扰动某球员单维能力，引擎行为必须单调响应（出手选择、命中率、防守对位、传球偏好随相关能力变化）。无响应 = 该行为路径是死的（脚本或常数短路），必须修复。这是涌现二字的机械守卫，做成常驻回归测试；
3. 新增任何"让画面更像"的常数 = 违反 C1；正确做法是把该诉求转化为能力维度、规则参数或评判准则。

## 6. 评判与反馈闭环（当前最大的缺口）

**痛点**：目前很难回答"这场模拟好不好、哪里不好、该动哪个子系统"。现有检测网只抓"不可能"（L1 不变量）和"宏观离谱"（三个标量统计门），抓不了"可能但完全不像"——于是引擎改动得不到真实度反馈，能力长期停滞，模拟与真实相去甚远。

**设计**（实现见 `quality.md` §2）：

1. **三层评判**：阶段评判（转换合法性/时间合理性）→ 回合评判（对照真实回合分布的结构化清单）→ 真实度指数（回合裁决的聚合）；
2. **参考系是分布不是单点**：真实比赛的回合级分布（时长、传球数、出手构成、PPP、失误率等）以**数据档案**形式存在；
3. **归因账本**：每条评判准则映射到责任子系统（decision / physics / semantics / officiating）。模拟产出缺陷账本，而不是一个笼统的"不像"；
4. **闭环**：跑批 → 逐回合评判 → 缺陷账本（准则 × 子系统）→ 走规则/能力通道调参 → 黄金哈希重冻结 → 再评判。每一轮循环必须有证据存档（`design.md` §2）。

这个闭环就是"引擎能力变强"的定义：**缺陷账本持续收缩，且每个收缩都能归因到一次具体的、走正通道的改动**。

## 7. 多联赛路线

| 联赛 | 状态 | 关键差异（LeagueProfile 内容） |
|------|------|------|
| NBA | 当前基线（`GameRules` 默认值即 NBA 形状：4×12min、24s/14s 重置、6 犯个人犯满、单节 5 犯 bonus + 节末两分钟特例） | — |
| FIBA | 路线图 | 4×10min、三分线 6.75m、5 犯个人犯满、单节 5 犯 bonus（无节末两分钟特例）、暂停结构、干涉得分判罚差异 |
| NCAA | 路线图 | 2×20min、30s 进攻时钟、犯规与 bonus/双 bonus 规则、交替拥有（无跳球） |

**验收（对应 C3）**：切换联赛 = 切换一份规则档案（JSON/数据结构），计时结构、几何、犯规政策、罚球程序全部随之生效；引擎代码路径零改动。在此之前，任何"看起来只影响 NBA"的规则逻辑也必须写成档案参数，不许先写死后迁移。

## 8. 成功判据（可验证）

北极星 O1 不可直接验收，以下判据全部达成即视为当前阶段成功：

1. **正确性**：标准种子矩阵下 L1 硬违反为 0，逐回合/逐阶段评判工件完整产出（无漏判回合）；
2. **真实度**：真实度指数达到 ≥0.90 目标线（回合/阶段裁决 Pass 率的加权聚合，公式随 M8 冻结，`quality.md` §2.3），且缺陷账本 top 准则的违反率**持续单调下降**（至少连续两轮校准循环）；
3. **涌现**：能力扰动测试全绿——每个能力维度至少有一条可观测的行为响应链；
4. **多联赛**：同一引擎内核在 NBA 与 FIBA 两份档案下各完成一场零违反比赛；
5. **闭环**：至少一轮完整校准循环（评判 → 归因 → 走通道调参 → 哈希重冻结）有完整证据存档；
6. **红线守卫**：内联行为常数 ≤ 20 处（豁免清单外；阈值权威见 `design.md` §3.1 M7），且新增常数的 PR 被守卫拦截过至少一次（负面对照）。
