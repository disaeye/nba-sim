# NBA-Sim · 球员属性与能力模型 · 数据规格设计

> 定位：球员与球队输入的单一事实源，定义分类学、值语义、锚点、可辨识性和耦合边界。
> 分工：本文档回答“能力是什么”；`docs/protocol.md` 回答“如何校准和验收能力消费”；`docs/tactics.md` 回答“球队如何组织能力”。
> 实现映射、维度接线和验证范围见 `docs/dev/status.md` 与 `docs/dev/gap.md`；跨模块取舍见 `docs/decisions.md`。
> 修订纪律：本文档只写稳定的数据规格，不写当前实现快照、轮次记录、命令或实测结果。

---

## 0. 为什么独立成文

1. **属性是引擎的输入，不是引擎的内部结构。** 球员档案与核心模拟之间不应有必然耦合——准确说是**单向依赖 + 窄接口**：引擎认识"能力的类型与经规则参数化的解释"，不认识"某个具体的球员"。roster 可以整体替换（真实数据标定、名册生成器、未来联赛档案），引擎零改动。这依赖一份独立、稳定、可单独演化的规格文档。
2. **值语义此前无家可归。** 类型在 `domain/data.rs`，解释权重在 `GameRules`/`ResolveConfig`，但"0.5 意味着什么、维度为什么存在、从哪类真实数据标定"没有任何文档认领。校准（`protocol.md` §1）与涌现验证（M9）都以它为前提。
3. **演化节奏不同。** schema 修订（分类学、规格）与引擎行为修订（管线、不变量）生命周期不同，混在 protocol.md 会互相拖累版本。

**耦合面声明（本文档的宪法）**：引擎对属性的全部合法知识 = §2 的类型 + §4 的映射边界。任何让引擎认识 roster 身份（球员 id 分支、剧本化行为）的改动违反宪章 C1，直接打回。

## 1. 设计原则

| # | 原则 | 一句话表述 | 守卫 |
| --- | ------ | ----------- | ------ |
| **PA1** | 能力与倾向分离 | 同一份技术可以打出不同风格；能力答"能不能"，倾向答"想不想" | 类型上两个 struct，禁止互相塞字段 |
| **PA2** | 归一与量纲分离 | 技术能力归一 0..=1（相对人口），体格带量纲（cm/kg）——体格是几何/物理事实，经映射层产生物理量（碰撞质量、reach、出手高度）生效，**不以归一形式进入效用或概率加权** | 体格字段不得出现在效用/概率公式（grep 守卫）；经映射层的物理通道合法 |
| **PA3** | 单一职责 | 一个维度对应**一种**可辨识的行为差异；一维承担两种职责 = 必须分化为多维 | 维度表逐维审查（§2） |
| **PA4** | 无死维度 | 每个能力**与倾向**维度必须有 ≥1 条消费链 + ≥1 条可观测的扰动响应链；死维度要么接线、要么删除，不允许“占位等未来” | 能力扰动测试（quality.md §6 / protocol.md §2.1 M9） |
| **PA5** | 值锚定于人口 | 0.5 的含义由锚点表（§3.1）定义；属性值只在相对人口的意义上存在 | 名册生成器 + 校准协议以锚点为基准 |
| **PA6** | 每维声明标定来源 | 维度表必须标注 observable（可从真实统计直接标定）/ latent（潜变量，联合标定） | 维度表；逆向标定管线的前提 |
| **PA7** | 机器面与展示面分离 | 底层维度全量，只服务涌现与校准；用户界面消费**派生投影**（复合轴 + 标签），投影永不回流 | 展示值纯函数派生；引擎 crate 零引用（grep 守卫，T6） |

## 2. 分类学（稳定 schema 约束）

### 2.0 总览

```
PlayerData（底层机器面 · 唯一事实源）
├── 身份     id / name / jersey / team_id / position（六类位置，§2.7a）
│           + offensive_role / defensive_role（赛前固定攻防角色，§2.7b）
├── 体格     height_cm / weight_kg / wingspan_cm✚ / age          （量纲，§2.1）
├── 能力     运动 6 维 + 进攻技术 8 维 + 防守与篮板 6 维 + 心智 2 维（归一，§2.2–2.5）
├── 倾向     持球 3 + 无球 3 + 防守 4✚ + 节奏 2 = 12 维           （归一，§2.6）
└── （v2 移除）roles: Vec<PlayerRole> —— 聚类标签降级为展示面纯函数（§2.7）

TeamTraits  战术风格 5 维（教练意志，§2.8）

展示面（上层 · 派生投影，§2.9）
  复合轴 8 + 原型标签 + 特质标签 —— 纯函数生成，永不回流引擎
```

✚ 标记需要在 schema 版本变更中显式登记的维度；角色不属于机器面本体。

### 2.1 体格层（量纲，非归一）

| 字段 | 语义 | 消费链 |
| ------ | ------ | -------- |
| `height_cm` | 身高 | → reach / release height / 对位指派参考 |
| `weight_kg` | 体重 | → 碰撞质量（挡拆、卡位、背身顶防） |
| `wingspan_cm`✚ | 臂展 | → reach（封盖半径、干扰高度、传球/接球半径） |
| `age` | 年龄 | 经营层成长曲线的输入；引擎层不消费 |

**纪律**：体格是**几何与物理事实的输入**，不是能力。它通过 §4 映射层产生派生量（`reach`、碰撞质量、出手高度），本身绝不进效用加权或概率公式——"高 = 会投篮"是数据相关性（§3.2 的事），不是引擎逻辑。

> `age` 是**时序身份字段**，不是体格物理事实：引擎层零消费，仅经营层成长曲线读取（§5）。放在本层是收纳约定，不改变"体格不进效用加权"纪律。

### 2.2 运动层（归一，6 维）

| 维度 | 语义（篮球定义） | 标定 | 消费链（→ 目标） | 扰动观测量 |
| ------ | ----------------- | ------ | ----------------- | ----------- |
| `speed` | 直线冲刺速度 | latent（与体格联合标定） | 运动学最大速度上限 | p99 移动速度、快攻参与率 |
| `acceleration` | 加速能力 | latent | 加速上限 | 达峰时间、短距冲刺距离 |
| `agility` | 横向移动与变向 | latent | 防守滑步最大速度、变向减速代价 | 被过率、横移速度 |
| `strength` | 对抗力量 | latent | 碰撞位移系数、掩护质量、卡位优势 | 掩护推开距离、背身成功率 |
| `vertical`✚ | 垂直弹跳 | observable（体测数据） | 与体格共同决定 reach、出手/封盖高度 | 封盖高度、被封盖率 |
| `stamina` | 耐力禀赋 | latent | 耐力容量初值与恢复系数 | 第四节速度衰减、分钟-效率曲线 |

> `agility` 与 `strength` 的语义在此**预先固定**，防止接线时退化为杂物桶。`stamina` 是禀赋（容量），运行态耐力归 physics 的 player state，引擎**绝不写回档案**。

> 可辨识性配对（PA6）：`agility` 与 `defense_perimeter` 的扰动观测量重叠（被过率）——运动禀赋与防守技术的分离只能靠联合标定（agility 同时影响进攻变向，def_perimeter 不影响），逆向管线必须把两者放进同一回归。

### 2.3 进攻技术层（归一，8 维）

| 维度 | 语义 | 标定 | 消费链 | 扰动观测量 |
| ------ | ------ | ------ | -------- | ----------- |
| `ball_handling` | 控球稳定性 | latent | 运球被抢风险、高压持球能力 | 被抢率、失误率 |
| `passing` | 传球**执行**精度（决策质量归 `decision_iq`） | observable（助攻/失误） | 传球成功率权重 | 助攻率、传球被断率 |
| `shooting_close` | 篮下出手精度（< 5 ft；挑篮/勾手） | observable（RA FG%） | Rim 区 FG% 技能分量 | 篮下 FG% |
| `shooting_near`✚ | 近筐出手精度（5–14 ft；抛投/短勾手/小后仰） | observable（非 RA 两分 FG%） | Near 区 FG% 技能分量 | 近筐 FG% |
| `shooting_mid` | 中距离出手精度（≥ 14 ft 且三分线内） | observable | Mid 区 FG% 技能分量 | 中距 FG% |
| `shooting_three` | 三分出手精度 | observable（3P%） | Three 区 FG% 技能分量、射程偏好派生 | 3P%、三分占比 |
| `free_throw`✚ | 罚球命中率 | observable（FT%） | 罚球裁决技能分量 | FT% |
| `finishing` | **对抗下**的终结完成度 | observable（对抗投篮 FG%） | drive 裁决、对抗上篮 | 突破得分率、AND-1 率 |

### 2.3a 统一出手分区（四区）

投篮相关的一切分类（能力维度、命中基准、效用选技、事件统计、评判准则）
共用同一份出手分区判定，落点 `domain::court::CourtGeometry::shot_zone`：

| 区 | 边界（距进攻篮筐） | 能力维度 | 命中基准 |
| ---- | ---- | ------ | ---- |
| `Rim` 篮下 | < 5 ft | `shooting_close`（对抗下由 `finishing` 承接） | `shot_make_rim` |
| `Near` 近筐 | 5–14 ft | `shooting_near` | `shot_make_near` |
| `Mid` 中投 | ≥ 14 ft 且三分线内 | `shooting_mid` | `shot_make_mid` |
| `Three` 三分 | 三分线外（含底角特例几何，优先于距离） | `shooting_three` | `shot_make_3pt` |

三分判定优先：一次出手先过 `is_three_point_attempt`（含底角更近的直线），
在线内才按距离分 Rim/Near/Mid。历史口径差异（引擎 8 ft、评判器 4 ft、
突破动作参数 14 ft）以本表为准统一；突破动作阈值（`drive_*_dist_ft`）
继续表达动作阶段选择，不承担出手分区职责。

分类事实统一取「释放时刻出手点」（`ShotRelease.pos`）：
`pending_shot_release` 挂起期球员可能移动，意图点与释放点会有偏差。

> 1. **close/finishing 可辨识性配对**：`shooting_close` 解释 Rim 区（< 5 ft）
>    出手族；`finishing` 继续表达**对抗下**的完成度（对抗 Rim 出手 + and-1 率
>    + 突破罚球率）。两维配对观测量：`shooting_close` ↔ 非对抗 Rim FG%；
>    `finishing` ↔ 对抗 Rim FG% + and-1 率。
> 2. **近筐特殊性的辩护**：只有篮下族设「对抗终结」独立维，是因为篮下是
>    **身体接触**裁决（垂直起跳、and-1、罚球制造），近筐/中距/三分跳投是
>    **几何干扰**裁决（openness）——两类裁决走不同管线，这是结构性不对称。
> 3. **背身打法不设维**：post 得分身份 = `shooting_close` + `strength` + 体格经映射层的涌现组合，不加 `post_game` 维度（2K 把 post hook/fade 分列为操作游戏的需要，模拟器里它派生即可）。

### 2.4 防守与篮板层（归一，6 维 · **位置轴**，v2 换轴）

**换轴原则**：`defense_on_ball`/`defense_help` 描述情境任务，不是稳定技能轴；对位和协防选择属于战术层，禀赋表使用外线防守、内线防守、抢断、封盖和篮板等可辨识维度。

| 维度 | 语义 | 标定 | 消费链 | 扰动观测量 |
| ------ | ------ | ------ | -------- | ----------- |
| `defense_perimeter`✚ | 外线防守：防持球、挡拆挤过、横移跟防 | observable（对位 DRtg 差分） | 对位者命中率调制、犯规率（外线情境） | 对位者外线 FG%、被过率 |
| `defense_interior`✚ | 内线防守：护框、背身顶防、协防站位 | observable（篮下 DFG% 差分） | 护框调制、犯规率（内线情境） | 对位者篮下 FG% |
| `steal` | 抢断**手法**（时机与手速，与赌博倾向无关） | observable（STL%） | 抢断概率技术分量 | STL% |
| `block` | 封盖手法与时机 | observable（BLK%） | 封盖裁决（与 reach 相乘） | BLK%、封盖犯规比 |
| `rebound_offensive`✚ | 前场篮板（技术与意识，v2 分化） | observable（OREB%） | 前板对抗 | OREB% |
| `rebound_defensive`✚ | 后场篮板（保护性卡位，v2 分化） | observable（DREB%） | 后板对抗 | DREB% |

> 分化理由：真实数据中前/后板能力持久分化（Rodman 型前板超神后板平庸，及反向的保护型），一维装不下两种技能；倾向层的 `offensive_rebound_frequency` 只表达"去不去抢"，表达不了"抢不抢得到"。

> 层名注记：`rebound_offensive` 是进攻技能，归入本层是**篮板一族对抗技能**的收纳约定（与 §2.3 的进攻技术层互斥原则不冲突——分组是文档结构，不是消费边界）。

### 2.5 心智层（归一，2 维 · 绑定具体决策点）

`decision_iq` 与 `off_ball_sense` 只绑定明确的决策点，不能退化为全属性乘数。

| 维度 | 语义 | 绑定的决策点 | 消费链 | 扰动观测量 |
| ------ | ------ | ------------- | -------- | ----------- |
| `decision_iq`✚ | 持球决策质量：传球预读、出手选择 | decision 候选评估（传球走廊预判、低质量出手剪枝） | 候选效用调制 | 助攻失误比、低质量出手率 |
| `off_ball_sense`✚ | 无球感觉：切篮时机、弹开走位、拉开空间；也可作为有限信息下的接球预估能力 | 无球候选（切篮/弹开）；接球预估 | 无球候选调制与接球预估映射 | 空位接球出手占比、切篮得分率、接球位置偏差 |

> **接球预估链（P-1 有限信息）**：接球人不得直读传球人的 `frozen_to_pos`，
> 只能按感知预估。`off_ball_sense` 决定他向新信息靠拢的速度：高 → 快速跟上
> 球的真实轨迹；低 → 停在自己最初的预判上。该维度因此同时是
> 「接球能不能跑到」的能力接入点，而**接得稳不稳**由 `ball_handling`
> 经 `capability::effective_catch_radius` 负责——两者是独立的通道，
> 不得混为一谈（见 `docs/dev/gap.md` §9.5 的层 A/层 B 分工）。

> 禁止任何"全局 IQ 乘数"式消费——每个心智维度只允许通过上表列出的决策点进入引擎。
> 防守侧心智（换防判断、协防站位、轮转纪律）v2 刻意留白：v1 `positioning` 曾承担此责但语义模糊，继任维度登记为 OQ-7，待接线证据定夺。

### 2.6 倾向层（归一，12 维 · v2 重构）

**推导原则**：倾向不是随手列举的“频率”，而是**决策空间的结构投影**，按三步推导：

1. **枚举决策上下文**：持球 / 无球 / 防守 / 转换与风险；
2. **每个上下文内枚举互斥选择轴**，球员在轴上取偏好位置；
3. **绑定纪律**：每个倾向必须绑定 decision 管线中一个具体的**候选生成器、效用项或运动强度目标**（transition_sprint 绑运动通道——枚举就此三种，新增通道须先扩本枚举；PA4 对倾向的机械化，无绑定的倾向不许进 schema）。

| 上下文 | 倾向 | 绑定点（候选生成器/效用项/运动通道） | 扰动观测量 | 权衡（同一枚硬币的两面） |
| -------- | ------ | -------------------------------------- | ----------- | -------------------------- |
| 持球 | `shoot_frequency` | 投篮候选效用 | 场均出手数、使用率（softmax 涌现输出） | 高→球权集中，与传球倾向此消彼长 |
| 持球 | `drive_frequency` | 突破候选效用 | 突破尝试率（次/百回合） | 攻框收益 / 陷入包夹风险 |
| 持球 | `pass_frequency` | 传球候选效用 | 场均传球数、传球占比 | 分享球 / 放弃自身出手 |
| 无球 | `cut_frequency` | 切篮候选 | 切篮尝试率、切篮接球得分占比 | 空切收益 / 离开投射位点 |
| 无球 | `screen_frequency` | 掩护候选 | 掩护设置次数（次/百回合） | 为队友做轴 / 消耗自身机会 |
| 无球 | `offensive_rebound_frequency` | 冲前板 vs 回防的候选权重 | 前板参与率（与对手转换得分成对报告） | 二次进攻 / 转换失分 |
| 防守 | `gamble_steal`✚ | 抢断尝试触发 | 抢断尝试率 + 被过率（**成对报告**） | STL↑ / 失位被过↑ |
| 防守 | `block_aggressiveness`✚ | 封盖起跳决策 | 起跳率、封盖犯规比、被晃起率 | BLK↑ / 被晃起、防守犯规↑ |
| 防守 | `help_aggressiveness`✚ | 协防触发阈值 | 协防触发率 + 自己对位者空位出手占比（**成对报告**） | 护框贡献 / 漏掉自己对位的空位↑ |
| 防守 | `physicality`✚ | 掩护/挤掩护/顶防强度 | 掩护接触强度、对抗犯规率 | 对抗收益 / 犯规风险（OQ-1） |
| 转换/风险 | `transition_sprint` | 转换跑动强度目标（运动通道） | 前场落位耗时、快攻参与率 | 快攻收益 / 后场篮板保护人数↓ |
| 转换/风险 | `risk_tolerance` | 高风险传球与高难度出手的惩罚折减 | 高难度出手占比 + 失误率（**成对报告**） | 高光表现 / 失误率 |

> **权衡型倾向的观测量必须成对报告**：gamble_steal 的收益侧（抢断）与代价侧（被过）同向上升——只断言收益侧的扰动测试会漏掉代价侧，等同于把权衡读成净收益。T5 扰动测试表对这类倾向须同时断言两侧方向。

**语义与命名注记**：`*_frequency` 字段表示效用偏好，不是产量；出手数、使用率和助攻数是决策系统归一采样后的涌现输出。禁止把产量目标直接写成倾向输入。

**可辨识性注记（§3.3 的倾向版）**：倾向经效用管线（与其他效用项相加、softmax 采样）才变成行为频率，因此倾向值 ≠ 观测频率——逆向标定必须把决策管线放进回归环，不能拿 FGA 率对 `shoot_frequency` 做单变量回归。

**刻意不加**（防杂物桶）：usage/球权率与 iso 偏好（由持球三维 + 战术方案涌现）；情绪/纪律/忠诚（经营层字段，§5）；临场手感（运行态噪声，非档案）。

> `TeamTraits.defense_aggression` 等战术意志与个体防守倾向的关系：**方案定基线，个体在其上调制**——相乘而非替代，禁止合并（双事实源）。

### 2.7 Roles 边界（v2 收窄）

"3&D 侧翼""挡拆巨兽"这类描述标签，与球员的攻防角色、位置的关系：

- **派生原型标签**：`(attributes, tendencies) → label` 的纯函数（聚类规则），
  归入上层展示面（§2.9）；UI 与球探报告消费它，不参与行为；
- **赛前攻防角色**：固定指派的战术板配置，属身份字段（§2.7b），
  整场不变，不随回合任务变化；
- **六类位置**：长期阵容位置归纳的风格标签，属身份字段（§2.7a）；
- **战术槽位**：战术档案声明的能力需求槽位（tactics.md TA3），
  逐回合按能力填充，与球员本体身份无关；
- **约束**：以上标签均不得成为引擎行为分支；引擎对位置与角色零读取
  （行为中立），角色也不得写回 `PlayerData` 之外的状态。

同理**明确不入本体**：OVR/badges/特质（属性组合的派生包装）、clutch（不可标定的噪声）、leadership/chemistry（经营层且是队伍级量）。

### 2.7a 球员位置（六类 · 身份字段，v2 新增）

`PlayerData.position` 是**身份字段**：每名球员恰一个六类位置，表达区别于
传统 PG/SG/SF/PF/C 的现代位置风格。分类依据**长期阵容位置**（借鉴
Cleaning the Glass 的出场时间法，按本项目六类单列 Center）：

| 位置 | 中文 | 判据（长期出场位置归纳） |
| ---- | ---- | ------ |
| `Point` | 控卫 | 主要承担 PG |
| `Combo` | 双能卫 | 持续兼顾 PG 与 SG |
| `Wing` | 侧翼 | 主要承担 SG 或 SF，或两者兼有 |
| `Forward` | 锋线 | 持续兼顾 SF 与 PF |
| `Big` | 内线 | 主要承担 PF，或持续兼顾 PF 与 C |
| `Center` | 中锋 | 主要承担 C，且很少承担 PF |

- **判据来源声明**：资料可核实时按长期出场位置归入；资料不足时由项目
  人工定类并记录依据（清册/名册 note 声明）。basketball-excel.com 使用
  同样六类名称，但其计算阈值未公开，本项目不假定为已核实事实；
  Cleaning the Glass 的判据按赛季出场时间推导，只有五类且 `big`
  涵盖中锋。
- **稳定语义**：位置是球员的长期属性，不随单场角色、换防或单回合动作变化；
  标签允许随赛季（多份数据源）更新，同一份档案内不变。
- **行为中立**：位置不提供任何能力加成，不进入效用/概率公式，不参与
  引擎行为分支（引擎对位置零读取，charter C1 的 id-中立同理）。
- **校验**：反序列化枚举 + `validate_team` 必填检查，不允许缺省值。

### 2.7b 赛前固定的攻防角色（战术板配置 · 身份字段，v2 新增）

每名球员在档案中声明**一个进攻角色与一个防守角色**。它们是教练赛前在

单次换防、突破分球或回合任务不改变角色；回合内的当下职责由实时
`action`、战术 `slot` 与防守对位表达，不改写角色。

目录参考 Basketball Index 的角色体系（进攻 12 类评价半场得分部署、

### 2.8 TeamTraits 边界

`pace / three_point_emphasis / rim_pressure / defense_aggression / rebound_emphasis` 保留 5 维，定义为**教练战术意志**。纪律：TeamTraits 只允许承载"全队统一执行的风格参数"；任何可由个体属性/倾向聚合派生的量（如全队平均篮板能力）不得重复放队伍层——双事实源。

### 2.9 上层展示面（派生投影 · 用户友好层，v2 新增）

**双面结构（PA7）**：22 能力 + 12 倾向 + 体格是**机器面**——为涌现与校准而完整；直接示人则用户不可适应（行业共识：FM 隐藏属性+可见分组、2K 模拟全量属性+界面六维、OOTP 真实值+球探 20–80 制）。故在其上包一层**展示面**：

- **纯函数投影**：`(底层全部维度) → 展示视图`，落点 `domain::scouting`（domain 零依赖、应用层皆可调用；**引擎 crate 禁止引用**，grep 守卫）；
- **永不回流**：引擎不读展示值；roster JSON 不存展示值；任何系统不得把展示值当真值写回；
- **独立版本化**（`scouting v1`）：改复合权重/标签阈值不动引擎、不动黄金哈希、不触发校准协议。

**球员资料四大块（展示分类 · 页面组织方式）**：

球员资料页以**得分、组织、篮板、防守**四块组织，每块直接展示底层维度数值，
**不把块内维度合并成单一数值**：

| 栏目 | 展示的底层维度 | 备注 |
| ---- | ------ | ---- |
| 得分 | 四区能力（§2.3a：shooting_close / shooting_near / shooting_mid / shooting_three）+ `finishing` + `free_throw` | 罚球以真实 FT% 量纲数值并列展示（Shaq 案例） |
| 组织 | `ball_handling` / `passing` / `decision_iq` | 持球创造；三值并列，不平均 |
| 篮板 | `offensive_rebound` / `defensive_rebound` | 前后场分开展示，禁止均值遮盖分化（Rodman 型） |
| 防守 | `defense_perimeter` / `defense_interior` / `steal` / `block` | 内外线分开展示，禁止简单均值（会抹平位置轴差异） |

运动能力与体格继续作为底层输入，展示于球员基础资料（身高/体重/速度等量纲数值）。
四大块之外仍可提供 8 轴复合视图（下表）作为球探/比较页的透镜；
复合轴是声明式加权和，权重表属 scouting 配置（版本化），永不回流引擎：

| 展示轴 | 聚合自（底层维度） | 备注 |
| -------- | -------------------- | ------ |
| 外线得分 | shooting_three / shooting_mid | 射术总览；罚球（free_throw）不入复合轴 |
| 内线得分 | shooting_close / shooting_near / finishing | 篮下与近筐完成 |
| 组织 | passing / decision_iq / ball_handling | 持球创造 |
| 防守 | defense_perimeter / defense_interior / steal / block | **禁止简单均值聚合**；取 max(perimeter, interior) 主显并标注形状/次轴 |
| 篮板 | rebound_offensive / rebound_defensive | |
| 运动 | speed / acceleration / agility / vertical / stamina | |
| 对抗 | strength | 单维轴；体格（身高/体重/臂展）以量纲数值并列展示，不参与归一聚合 |
| 心智 | decision_iq / off_ball_sense | 与"组织"共享 decision_iq——不同透镜允许共享底层维度 |

锚点表（§3.1）穿透投影：复合值 0.5 = 联盟中位。位置敏感轴（防守）禁止简单均值聚合——见各轴备注。

**倾向的展示**：倾向**不以数字示人**——展示为文字化派生标签：

- **原型标签（archetype）**：§2.7 派生角色的聚类输出（"3&D 侧翼""组织核心""护框中枢"…）；
- **特质标签（trait tag）**：阈值规则集 → 标签（"赌博式抢断""转换箭头""前板嗅觉""高对抗"…），每条标签声明其底层阈值组合；
- 必要时关键倾向给五档文字（极低…极高），刻度方案见 OQ-5。

**刻度**：0–100 / 20–80 / 字母制皆为同一底层值的**换肤**，属 UI 配置而非本体；锚点语义保证跨刻度一致。

**球探迷雾（预留）**：经营层可在展示面之上再包一层噪声/不确定性视图（对投影加噪、按球探能力模糊）；引擎与展示面均不感知——纯视图设计保证其随时可加（§5）。

### 2.10 刻意不加登记（能力侧 · 防杂物桶）

与 §2.6 的倾向排除清单对应，能力侧排除同样必须登记——未登记的排除是未来 scope creep 的入口：

- **造进攻犯规**（charges drawn）：需要独立的带球撞人裁决和可辨识消费链；在该规格建立前不进入属性本体；
- **五五开/松球争抢**：只有在定义独立的争抢消费链和观测量后，才能从篮板维度中分离；不得把篮板维度永久当作无依据的代理；
- **惯用手**：若进入输入规格，应作为方向性倾向并声明突破与防守 shading 的消费链；不能作为未声明的隐含身份字段。

新增能力维度必须先在本表销账（证明不可归入现有维度），或修正本表。

## 3. 值语义与三大规格

### 3.1 锚点表（PA5）

每个归一维度的值语义锚定于**联盟人口分布**：

| 值 | 含义 |
| ---- | ------ |
| 0.02 | 灾难级（联盟最差尾） |
| 0.20 | 边缘轮换 |
| 0.50 | 联盟轮换级中位 —— **校准基准点** |
| 0.80 | 首发精英 |
| 0.95 | 最佳阵容级 |

**锚点口径（单一）**：锚定**联盟无条件边际**——0.5 = 全联盟全体球员的中位，与位置无关。位置条件差异（中锋群体的速度分布）由 §3.2 的联合相关性建模承载，不改变锚点读数口径。展示面如需位置透镜（"同位置分位"），由 scouting 配置声明换算，但底层值口径唯一。

**后果（必须遵守）**：`base_rates + (skill − 0.5) × w` 类公式的校准依赖此人口假设。校准（`protocol.md` §1）与名册生成（§3.2）都以锚点为共同基准；名册生成器必须同时声明位置构成先验，避免均值和位置构成漂移。

### 3.2 人口分布规格（跨字段相关性）

- 每个归一维度声明**边际分布形状**（如 Beta(α,β) 或分位数表），体格声明**量纲分布**；
- 声明**联合相关性**：身高—速度—位置存在强联合分布（2.16m + 0.99 speed + 0.99 agility 物理上离谱）；
- 实施形式：`validate()` 对离谱组合发**警告**（不报错——Bol Bol 确实存在），名册生成器按声明分布+先验采样；
- 消费方：经营层球探/比较（"这队缺什么"全是分位数运算）、校准（§3.1）。

> **冻结边界**：联合相关性的数学形式属于实现/校准层；本规格只冻结警告而非错误的处理原则，以及名册生成必须遵守已声明的分布和位置先验。

### 3.3 可辨识性规格（标定映射）

每个维度必须回答"从哪类真实数据标定"——已在 §2 各表"标定"列声明。两类：

- **observable**：直接映射真实统计（`shooting_three↔3P%`、`steal↔STL%`…），逆向管线 `真实数据 → ratings` 可单维回归；
- **latent**：无可直接观测对应（`agility`、`strength`…），由联合模型或先验标定（与 FM/OOTP 同法）。

**这张映射表同时是正向合同**：扰动测试（M9）逐维观测的指标 = 本表的"扰动观测量"列。逆向通道（真实联赛数据 → roster）是否存在，决定引擎能否吃真实数据——经营游戏的命门。

**配对登记（联合标定清单——逆向管线必须成对/带协变量回归）**：

| 维度簇 | 混淆来源 | 处置 |
| --- | --- | --- |
| `shooting_close` ↔ `finishing` | 同一出手族（RA FG%） | 见 §2.3 配对：非对抗 RA（defender 4–6ft+）↔ 对抗 RA + and-1 + 突破罚球率 |
| `agility` ↔ `defense_perimeter` | 被过率同源 | 见 §2.2 注记：agility 同时影响进攻变向，联合回归 |
| `passing` ↔ `decision_iq` | AST/TO 族是执行×选择的联合产物 | 助攻/失误对两维联合回归；正向观测量分流：传球被断率（执行）↔ 低质量出手率（选择） |
| `block` ↔ `wingspan`/`vertical`/`height` ↔ `block_aggressiveness` | BLK% 是手法 × reach × 起跳倾向的乘积 | 体格经体测直接可得：先固定 reach 再回归手法；封盖犯规比分离起跳倾向 |
| `decision_iq` ↔ `shoot_frequency` | 低质量出手率是 usage–efficiency 权衡的产物（高出手倾向本身推高它） | 逆向标定以出手量/使用率为协变量；正向扰动观测量取"同出手量下的低质量出手率" |
| `off_ball_sense` | 空位接球出手占比受球队传球意愿与 shoot_frequency 混淆 | 以切篮族为主观测量（切篮尝试率/得分率），接球出手类仅作参考 |
| `shooting_three` ↔ 出手构成（OQ-6 关联） | 聚合 3P% 是 pull-up 与 C&S 的构成加权混合 | 即使暂不加维，逆向标定也须以 C&S 占比为协变量，否则把出手选择混进技能 |

### 3.4 档案不可变原则

PlayerData 在比赛运行期**只读**。运行态量（当前耐力、犯规数、士气）住在 engine/physics 的 player state，以档案为初值——引擎绝不写回档案。这保证确定性回放不依赖档案突变的顺序。

## 4. 与引擎的耦合边界（输入规格的执行细则）

```
PlayerData（本规格）──► 映射层（domain::capability 纯函数）──► 物理量/概率调制
                              ▲
GameRules / DecisionRules / ResolveConfig（权重与曲线形状，protocol.md P6 通道）
```

- **映射层集中**：`归一属性/体格 → 物理量`（`effective_max_speed`、`effective_reach`、`release_height`…）收敛为一个纯函数模块（建议 `domain::capability`，零依赖可单测，physics/decision/officiating 共用）。曲线形状（线性/幂次/floor）全部由 rules 参数化。
  - **反例（禁止模式）**：内联 floor 把有效区间压缩成无效区间，且常数游离于规则通道之外。曲线形状和 floor 必须属于规则通道。
- **解释权重归规则**：属性如何影响概率/效用（`player_skill.*_weight`、`tendency_weight` 等）全部走 GameRules 体系；本规格只定义维度与值语义，不定义权重数值。
- **禁止事项**：
  1. 引擎任何分支依赖球员 id / roster 身份（C1）；
  2. 子系统内散落属性乘法（必须经映射层）；
  3. 属性直接当物理量用（0.88 不是 0.88 ft/s）；
  4. 运行期写档案（§3.4）。

## 5. 经营层预留（非规范）

`docs/charter.md` 将经营（成长、选秀、交易、薪资）排除在模拟引擎范围外。经营字段属于引擎档案之外的包络层，不得进入 `PlayerAttributes` 或影响引擎行为。若未来扩展范围，必须先修订宪章；球探迷雾也只能包裹展示投影，不能回流为机器面输入。

## 6. 迁移路线（分类学先行，接线在后）

**顺序原则**：先确定分类学，再建立映射层和锚点/分布约束，最后接入扰动验证与展示投影；分类学变化会影响所有下游消费链。

| 步 | 内容 | 依赖 | 验收 |
| ---- | ------ | ------ | ------ |
| T1 | **分类学修订**：确定 schema v2 的防守轴、终结/篮板维度、罚球/垂直/臂展、心智绑定和角色边界 | 无 | schema、语义和兼容策略经过规格审查 |
| T2 | **映射层**：建立 `domain::capability` 纯函数；曲线和边界参数走规则通道 | T1 | 子系统通过映射层消费属性 |
| T3 | **锚点与分布规格**：声明锚点、边际分布、联合约束和名册生成规则 | T1 | 生成/导入档案能报告分布和相关性问题 |
| T4 | **罚球能力接线**：将 `free_throw` 接入罚球结果通道 | T1 | 罚球能力扰动产生单调响应 |
| T5 | **能力/倾向接线与扰动 harness**：逐维登记消费链和响应量，并纳入持续验证 | T1–T4 | `protocol.md` §2.1 M9 验收 |
| T6 | **展示面投影**：建立纯函数复合轴、原型/特质标签和版本化配置 | T1 | 展示值纯派生且不回流引擎 |

> T1 触发黄金哈希重冻结（builtin 名册变化），走 `protocol.md` §1 协议。

## 7. 开放问题登记

| # | 问题 | 决策状态 |
| --- | ------ | ------ |
| OQ-1 | `physicality` 一维两用（进攻掩护+防守对抗）vs 分为两维 | 判据（人口统计，接线前即可回答）：真实数据中掩护有效性（screen assists / PnR 效率差分）与顶防有效性（post DFG% 差分）在控制 strength 与体重后，偏相关是否 ≈0 或为负——是则拆两维，否则维持一维两用 |
| OQ-2 | 射程偏好：派生量（由三区技能曲线派生）vs 独立倾向维度 | 暂定派生（DeRozan 型由技能形状涌现）；若扰动测试发现射程分布失真再引入 |
| OQ-3 | 经营层是否进目标范围 | 不属于当前引擎规格；范围变化须先修订 charter §2 |
| OQ-4 | 协议层负荷数据接口 | 由未来经营层需求另行定义，不进入当前属性规格 |
| OQ-5 | 展示刻度方案 | 属于展示配置，不影响机器面语义 |
| OQ-6 | 持球投 vs 接球投（pull-up vs C&S）：单维 + 情境罚项（openness/移动状态）建模是否足够 | 暂定不加 `shooting_off_dribble` 维；若扰动测试发现 pull-up 型与 C&S 型球员三分产出分布同质化，再引入（届时三区 × 两种出手方式会翻倍投篮维度，须权衡；逆向通道协变量要求见 §3.3 配对登记） |
| OQ-7 | 防守轮转/责任维度是否需要独立心智轴 | 先用既有防守能力与倾向验证轮转恢复、协防护框和漏人率；若无法解释，再提出带消费链和观测量的独立维度 |
